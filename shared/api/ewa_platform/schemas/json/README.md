# EWA JSON Schema catalog

Source catalog review: 2026-10-11. Ten checked-in JSON files provide mirrors/drafts for non-Python consumers. They parse and pass the installed Draft 2020-12 metaschema check; that proves schema syntax, not parity with runtime acceptance. Shared HTTP uses the actual Python predicates/mappers/Pydantic models. Source search found schema references in comments/tool descriptions, not a runtime JSON-file validation loader in this package.

Historical `/schema/amka/` ids remain in envelope/desktop/domain/orchestration files. They are identifiers in the source, not evidence that these contracts belong to marketing AMKA or that remote URLs were fetched/published. [Taxonomy](../../../../../documentation/product/ewa/EWA-VS-AMKA-TAXONOMY.md) owns that distinction.

For aggregators select the intended local `$defs` target rather than treating the root as an enforcing union. Confirm reference resolution, dialect, required fields, extra-property rules and version policy against runtime accepted/rejected examples. Incompatible contract evolution should explicitly version the file/Python/wire/client boundary; the existence of a v2 file does not automatically switch all consumers.

This audit changed this guide only. Schemas, Python validators and version constants were left unchanged, with defects recorded separately.
