# Регрессия: интерактивный маркетинговый дашборд

Краткий чеклист после правок в `OverviewInteractiveDashboard`, виджетах, `dashboard.py` / `summary.py` / `dashboard_bundle_slices.py`.

**Приёмка MVP (2026-04-18):** полный прогон разделов ниже на стенде; `podman logs` / `docker/logs/stack0/eliteew-api-prod/` без новых `ERROR`/`Traceback` по сценарию дашборда; фронт — `pnpm run build:react-compiler` (хронология — `git log`, monthly worklog retired).

## Пресет и макет

1. Открыть проект → Обзор → **Открыть дашборд** в шапке (кнопка с иконкой макета) или пункт **Дашборд** в левой навигации (`mc_view=overview_dashboard`).
2. Выбрать пресет в селекторе; убедиться, что в подписи есть **v{version}**.
3. Добавить виджет из каталога; проверить tooltip описания у опций (если есть i18n `catalogDesc.*`).
3b. **Пресет витрины:** применить пресет **`all_widgets_showcase`** (если миграции применены на стенде); убедиться, что макет создаётся без ошибок, сетка прокручивается (см. п. 19), все плитки рендерятся.

## Сетка и сохранение

4. Перетащить плитку; убедиться, что макет сохраняется (нет вечного «ошибка» без toast при сбое сети — при имитации сбоя должен быть toast / возможность refetch). После успешного сохранения позиций — **краткий screen reader анонс** (`layoutSavedLive`, волна 4 / L.116).
4c. **C.26 (Wave 20):** при сохранении виджета с заведомо малыми `w`/`h` (старые данные или подделанный запрос) в ответе/API после записи размеры **не ниже** минимумов каталога (`registry.ts` / сервер `MARKETING_DASHBOARD_WIDGET_GRID_DEFAULTS`).
4d. **C.34 (Wave 21):** при полном макете (число плиток = `max_widgets_per_layout` из usage-stats) — добавление / дубль / вставка из буфера даёт отказ (toast); импорт JSON с большим числом плиток — отказ на клиенте и на API; **первое** применение пресета с шаблоном выше капа — **400** на API; клон макета «сверх капы» — **400**.
4e. **C.28 (Wave 22):** после drag/resize сетки или кнопок ± в chrome — в **`PATCH .../dashboard-widgets/{id}`** поля **`grid_position`** с **целыми** `x` / `y` / `w` / `h` (Network); после refetch позиции не «плывут» из‑за дробей.
4f. **C.29 (Wave 22):** у **незаблокированной** плитки — в chrome кнопки **±** ширины и высоты (шаг **1** клетка); **Tab** до кнопок без мыши; в диалоге **`?`** — строка **`shortcutTipTileResize`** (`ru` / `en`).
4g. **C.31 (Wave 22):** пользователь **только просмотр** (`!allowMarketingWrite`) — сетка **не** перетаскивается и **не** ресайзится; плитки **`static`** в RGL; точки редактирования макета в тулбаре (добавление, импорт, undo и т.д.) **недоступны**, если так в UI.
4h. **C.25 (Wave 22 / UX 2026-07):** **`RGL_COMPACT_TYPE = null`** и **`RGL_PREVENT_COLLISION`** в `overviewDashboardGridPolicy.ts` — свободные ряды снизу (можно утащить/растянуть плитку ниже текущего низа сетки без «схлопывания»); мышью resize по ручкам `se`/`s`/`e`; в связке с п. **19** — длинный макет и скролл без потери тулбара.
4b. **C.30 (Wave 19):** плитка с **блокировкой** (`is_locked` / «закрепить» в chrome) — при включённом редактировании **не** перетаскивается и **не** меняет размер (drag/resize отключены для `static` в RGL).
5. Свернуть/развернуть подсказку пресета (`details`), если отображается.
6. **Экскурсия:** шаги `overviewMode` (якорь `data-mc-guide="overview-mode"` на обзоре) и `widgetChrome` (первая плитка дашборда); озвучка **`ru/`** и **`en/`** в `public/audio/marketing-cabinet-guide/` (генерация EN — Silero `language=en` в stack9, см. README каталога).

## Плитки

7. **Tasks / Alerts:** увеличить `maxItems` (если доступно в chrome), проверить длинный список и прокрутку (виртуализация при **≥ 24** строк — `DASHBOARD_LIST_VIRTUAL_THRESHOLD`). Фильтры/сортировка на плитке → PATCH `widget_config` → refetch; **открытые алерты** при фильтрах: счётчик из `alerts_open_count` в срезе, иначе **Wave 24** — клиентский пересчёт по `dashboard.alerts` с теми же фильтрами статуса/severity.
8. **Списки campaigns / segments / researches:** при `GET .../dashboard?layout_id=...` строки из **`widget_list_slices`** совпадают с фильтрами плитки; **`filtered_total`** в срезе согласован с числом строк при том же фильтре (до капа `maxItems`). Фильтр/сорт на плитке → PATCH → refetch; **Открыть раздел** подставляет `mc_ops_*` в URL и фильтрует список в **Кампании / Сегменты / Доказательная база** (evidence). **CSV:** при ненулевом списке на плитке — кнопка экспорта для **campaigns / segments / researches** (видимые строки после среза).
8b. **JTBD / Value props / Competitors:** плитки **`jtbd_stories`**, **`value_props`**, **`competitors`** — срезы **`job_stories`** / **`value_propositions`** / **`competitors`** в **`widget_list_slices`**; фильтры и сорт на плитке → PATCH → refetch; клик по строке ведёт в **JTBD** / **Value props** / **Анализ**; при ненулевом списке доступен **CSV** (в т.ч. **competitors**); **Открыть раздел** подставляет в URL **`mc_ops_jtbd_*`**, **`mc_ops_value_prop_status`**, **`mc_ops_competitor_type`** — списки в разделах фильтруются согласованно.
9. **Плитка `imc_recent`:** при наличии в макете в ответе dashboard есть **`imc_research_runs`** и срез **`widget_list_slices[…].imc_research_runs`**; клик по строке ведёт в **IMC** с выбранным run; фильтры **`status`** / **`type_key`** и сортировка согласованы с сервером; подписи **`type_key`** в UI и в опциях фильтра локализованы (**Wave 24**, `imcView.researchType.*`).
10. **Chart metric:** выбор метрики и окна дней; ключ React Query уже включает `dashboardSeriesWindowDays` (комментарий **F.61**, Wave 24). Легенда, `aria-label`, экспорт **PNG**; пустой ряд — один блок **`emptySeries`** (дубль второго абзаца убран, Wave 24).
11. **Canvas:** переключить Markdown ↔ Drawing; сохранить; при **ошибке сохранения** — кнопка сброса к серверу восстанавливает контент. Лимиты **фигур / страниц** tldraw — сообщение в плитке при превышении; **экспорт PNG/SVG** — при огромном рисунке возможен отказ «файл слишком большой» после даунскейла. Заготовка e2e отката: `e2e/marketing-dashboard.wave2.spec.ts` (G.65).
12. Неизвестный `widget_key`: плитка показывает ключ и подсказку, не пустой экран; при необходимости — **Обновить дашборд** (`unknownWidgetRetry`).
12b. **D.35–D.46 (Wave 23):** кнопка **?** у заголовка — подсказка без внутренних имён полей API; **Переименовать** — модалка; кнопки в шапке плитки (включая удаление) — единый визуальный размер; меню **⋯** и **ПКМ** — те же действия (копирование JSON только из меню или вставка с тулбара); **chart_metric** / **chart_metrics_bar** — тултип на графике не обрезается прокруткой тела плитки; плитка **воронки** при пустом срезе — текст `funnelListEmpty`.
12c. **E/D/F (Wave 24):** у интерактивных строк списковых плиток (tasks, alerts, кампании и др.) **hover** и **фокус с клавиатуры** (`:focus-visible` / `focus-within` где нужно) используют общие классы **`DASHBOARD_LIST_ROW_SHELL_*`** (`desktopListTokens.ts`); плитка **`ai_activity`** при пустом списке — **`aiActivityListEmpty`**, в каталоге **`minH`** выше (**D.43/D.45**); текст при отсутствии блока **`analytics`** — **`analyticsNotLoaded`** (`ru`/`en`).
12d. **Readiness (D.42/D.43, 2026-04):** плитки **`funnel`** (пустой срез), **`ai_activity`**, **`imc_recent`** (пустой список) — кнопка **`retryLoad`** при наличии refetch; **`funnel`** / **`ai_activity`** — дополнительный переход в раздел (**`overview.openAction`** / **`aiActivityOpenStudio`**); **`chart_metric`** при пустом ряде (`emptySeries`) — **`retryLoad`**.
12e. **Wave 25 (L.115):** при видимых плитках ссылка **«к первой плитке»** (skip-link) переводит фокус на **первый интерактив** внутри `#mc-dashboard-first-tile` (не только скролл к якорю); следующий **Tab** логично уходит по плитке. Vitest: `dashboardFirstTileFocus.test.ts`.

## Операции (deep link)

13. Из плитки **Открыть** задачи/алерты с фильтром: в URL появляются `mc_ops_task_status`, `mc_ops_task_priority`, `mc_ops_alert_status`, `mc_ops_alert_severity` — в разделе **Задачи / Алерты** список отфильтрован; при нуле совпадений — пустое состояние «нет по фильтру». ## Служебное

14. **Убрать дубликаты** (если доступно): подтверждение и успешный toast.
15. **Экспорт макета** (если есть): JSON скачивается.
15b. **Импорт макета (Wave 19, B.20):** файл экспорта (`_exportSchemaVersion` 1, `layout.widgets`) → **`POST .../dashboard-layouts/import`** — создаётся **новый** активный пользовательский макет; предыдущий активный деактивируется; число плиток и ключи валидируются на API.
15c. **Пересборка из шаблона пресета (Wave 19, B.18):** в селекторе выбран пресет, для которого уже есть макет `type=preset` → кнопка **«Пересобрать из шаблона»** → после подтверждения плитки и `layout_config` макета совпадают с актуальным `template_config` пресета в БД. **L.116 (Wave 20):** после успеха — краткий **screen reader** анонс (`presetRebuildLive`, без PII в имени файла).
15d. **L.116 (Wave 20):** после успешного **импорта** макета — краткий анонс `layoutImportLive` (число плиток).
15e. **L.116 (Wave 21):** после bootstrap пустого дашборда (пресет **`minimal`**) и после обычного применения пресета — краткий анонс `presetAppliedLive` (лучше с **отображаемым** именем пресета).
16. **Пресеты B.15 (Wave 16):** при нескольких пресетах — фильтр категории и поиск сужают список в селекторе пресета; при нуле совпадений — текст «Нет пресетов по фильтру…» (`presetsFilterEmpty`). **B.17 (Wave 18 + 20):** под селектором — компактные кнопки до **трёх** последних применённых пресетов; история в **`sessionStorage`** и **`localStorage`** (`dashboardPresetHistory.ts`, ключ `mc-dashboard-preset-history-local:{projectId}`, до 10 имён; при первом чтении пустого local — подмешивается session).
17. **Телеметрия A.12 (Wave 15):** после того как активный макет загружен и контейнер сетки измерен (`width > 0`), один раз на комбинацию «монтирование + `projectId`» отправляется **INFO** в `POST /api/v1/monitoring/logs` (**только production**): `serviceName: MarketingCabinet:DashboardTTI`, `message: overview_dashboard_interactive`, в `metadata` — `msToInteractive` и `visibleWidgetCount` (без UUID проекта и без пользовательских строк). В development событие уходит в консоль через `ServiceLogger`.
18. **Превью пресета с диффом (Wave 17, B.16):** выбрать пресет — модалка показывает состав плиток пресета и отдельным блоком плитки **текущего активного макета**, чьих типов нет в шаблоне пресета (перед `POST …/dashboard-layouts/from-preset`).
19. **Высота области сетки (Wave 17, C.25):** длинный макет при низкой высоте окна — вертикальная прокрутка **внутри** обёртки сетки (`max-h` относительно `dvh`), тулбар дашборда остаётся доступен (липкий / в шапке — как в текущем режиме).

## API (опционально, со стендом)

20. `GET .../dashboard?layout_id=<active_layout_uuid>` — в ответе **`widget_list_slices`**: `tasks`, `alerts` (и при соответствующих виджетах — `campaigns`, `segments`, `researches`, `job_stories`, `value_propositions`, **`competitors`**, `imc_research_runs`), для алертов при необходимости **`alerts_open_count`** после серверных фильтров; в объектах срезов — **`filtered_total`**; при плитке **`imc_recent`** — также верхнеуровневое **`imc_research_runs`**.
20b. **`POST .../dashboard-layouts/import`** — тело как у экспорта (`_exportSchemaVersion` **1**, `layout`); неверная версия → **400**. **`POST .../dashboard-layouts/from-preset`** с **`rebuild_existing: true`** пересобирает только макет **`type=preset`** с совпадающим именем.
21. Массовые `PATCH` макета / виджета — после порога ожидаем **429** и `Retry-After` (см. `MARKETING_DASHBOARD_WRITE_RATE_LIMIT_PER_MIN`).

Дополнять этот блок новыми сценариями ИМК/RAG при смене контрактов (исторический пункт **M.135**; 100+ backlog soft-retired).
