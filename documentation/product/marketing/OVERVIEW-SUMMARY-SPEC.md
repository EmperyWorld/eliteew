# Быстрая сводка маркетингового кабинета (Overview)

Назначение: **операторский снимок проекта** — не финансовый executive dashboard. Ответы на вопросы: есть ли базовые артефакты, насколько сущности связаны между собой, не устарели ли материалы, есть ли очевидные разрывы и алерты.

## Вопросы бизнеса и где смотреть в UI

| Вопрос | Где в UI |
|--------|----------|
| Насколько «собран» проект по стратегии и связям? | Плитка «Готовность», блок «Состав оценки готовности», таблица coverage ниже |
| Связаны ли JTBD с ценностными предложениями? | Плитка «Покрытие JTBD», строка `jtbd_to_value_props` в секции связей |
| Сколько сущностей заведено (объём)? | Плитки сегменты / кампании / алерты / AI run-ы — **счётчики объектов**, не проценты |
| Где проседает свежесть SWOT/контента? | Секция «Связи и свежесть» (freshness) |

## Язык интерфейса и эта спецификация

В UI маркетингового кабинета формулировки для маркетологов и руководителей короче, чем в этом документе; точные доли и отличие «готовность vs покрытие JTBD» продублированы в справке по блоку «Готовность» (`help/blocks.*.json`, ключ `overview.metric.readiness`). Здесь — канон для продуктовой и операторской сверки с API.

## Глоссарий (RU → EN)

| RU (UI) | EN | Смысл |
|---------|-----|--------|
| Готовность проекта | Project readiness | Индекс **0–100**, взвешенная комбинация пяти компонентов (см. ниже). **Не** равен плитке «Покрытие JTBD». |
| Состав оценки готовности | Readiness composition | Пять компонентов 0–100: база стратегии, операции, **среднее** по метрикам связей, свежесть, связность стратегии. |
| Покрытия связей (в составе готовности) | Linkage coverage (in readiness) | **Средний процент** по строкам блока coverage, **только по метрикам, у которых знаменатель > 0** (нет воронок → строка не участвует в среднем). |
| Покрытие JTBD | JTBD coverage | Доля **job stories** проекта с привязкой к **value proposition** этого проекта (`addressed_job_ids`). Отдельная плитка. |
| Связность стратегии | Strategy coherence | Индекс целостности связей (`strategy_integrity_score` и детализация). |
| Свежесть материалов | Material freshness | Агрегат по SWOT / исследованиям / контенту / AI-активности. |

## Формула готовности (канон)

Веса **фиксированы** в коде API (`READINESS_WEIGHTS` в `api/routers/marketing_cabinet/summary.py`):

- База стратегии (артефакты): **35%** — доля заполненных слотов среди JTBD, VP, SWOT, конкуренты, исследования, контент.
- Операции: **20%** — сегменты, кампании, воронка, задачи, AI runs (бинарно «есть / нет»).
- Покрытия связей: **20%** — среднее процентов по строкам `coverage` с `total > 0`.
- Свежесть: **8%** — среднее баллов по зонам свежести.
- Связность стратегии: **17%** — `strategy_integrity_score`.

Ответ dashboard дополняется полем **`readiness_meta`**: веса, **вклад в балл** по компонентам (последний компонент подбирается под итог с округлением), **метаданные среднего по coverage**: сколько строк участвовало в среднем, сколько всего слотов метрик.

## Объём данных vs индексы

Плитки **сегменты / кампании / открытые алерты / AI run-ы** показывают **количество** сущностей или открытых алертов — **не** процент готовности. Их нельзя сравнивать напрямую с «Готовностью» без учёта смысла.

## Чего на этом экране нет (пока)

Классический **маркетинговый отчёт для CMO** по performance (выручка marketing-sourced, CPL, ROMI, ROMI по каналам, вклад в pipeline, сквозная воронка до сделки) требует **интеграций и ТЗ** на источники данных. Текущая **Быстрая сводка** не подменяет такой отчёт: она про **целостность данных и связей в кабинете**, а не про финансовый эффект кампаний.

## Executive snapshot (UI)

Верхний блок «сводки» на фронте собирается из уже отданных API полей: приоритетный **gap** (critical → high → …) и **самый низкий компонент** из `readiness_breakdown` как ориентир «где проседает готовность». Это нарратив для оператора, не новая формула на сервере.
