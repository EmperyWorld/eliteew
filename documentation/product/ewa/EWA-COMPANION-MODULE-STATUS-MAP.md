## Persona-to-model chain

Profile seed → [config resolvers](../../../shared/api/ewa_platform/companion/config.py) / [persona style](../../../shared/api/ewa_platform/companion/affective/persona_style.py) / saved character → [prompt-block cache and canon](EWA-COMPANION-PROMPT-BLOCKS.md) → [main system builder](../../../shared/api/ewa_platform/companion/turn/phases/main_llm_prepare.py) → interactive completion → guarded reply/actions → profile/cache and optional episodic/evolution side effects.

Config remains numeric/string fallback source; prompt prose also has PG overrides. A block that differs from the consumer's canonical constant can win over legacy persona strings. Character/preferences/context are stored profile state, not just static config. Planner/tool orchestration can terminate before the main reply model, but trust/other sidecars may already have run. Action suggestions are filtered and some execute later on the client; registered tool capability is not successful task completion.

A historical ROLE/numeric alignment pass and retired persona dump explain the prior report's provenance. Current source defaults and tests support the matrix; linguistic alignment is editorial intent, not a measured behavioral or model-quality result. The old external “Anchor Completion Report present” claim is not retained as current evidence without an identifiable source artifact.
