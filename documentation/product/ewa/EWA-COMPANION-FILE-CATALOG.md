# EWA companion file catalog and document mutations

Reference · source contract reviewed 2026-10-11. This guide owns the companion workspace, folder selection, file-tool mutations and confirmation boundaries. [Catalog-discuss](EWA-COMPANION-CATALOG-DISCUSS.md) owns body injection; [multi-intent orchestration](EWA-COMPANION-MULTI-TASK-ORCHESTRATION.md) owns compound/file-study/TurnPlan routing; [operations](EWA-COMPANION-OPERATIONS-PANEL.md) owns task HTTP/SSE and client delivery. Their review scopes are independent. General Content Manager, DocEditor, extraction, agentic execution and live storage remain separate acceptance work.

## Workspace and identity

The standard companion list/search scope is desktop item `ewa_file`, displayed as EwaFile, with `owner_only=True`. The main Unified Content DB list implementation includes rows whose folder is `ewa_file` or matches `ewa-task-%`; this is a string scope, not a recursive verification of the desktop folder tree. The shared row helper likewise accepts the task prefix. Source: [shared/api/utils/ewa_companion_folder.py](../../../shared/api/utils/ewa_companion_folder.py) and [shared/api/ewa_platform/companion/storage/catalog_scope.py](../../../shared/api/ewa_platform/companion/storage/catalog_scope.py).

Main application content storage and EWA task/profile persistence use distinct pool entry points. File bodies/catalog queries belong to the main DB; pending task runs and file focus belong to the EWA pool. An alternate OAuth subject can be supplied to catalog search; body reads/writes still use the supplied content owner id. See the named/direct/focus distinction in the read guide.

The workspace scope is not universally enforced by every tool. Named lookup uses scoped queries, but explicit ids and retained deictic focus can bypass fresh folder lookup. `resolve_file_target` accepts a stripped explicit id of at least eight characters without checking UUID, existence or current permissions; a later consumer must perform its own validation. Focus-derived matches default permission flags to true when no row metadata exists. `file_open` emits an action without reading the body. Direct append and owner-byte paths have their own authorization, without a folder check. Do not infer universal EwaFile containment from the common query helper. Source: [shared/api/ewa_platform/companion/orchestration/flows/catalog_resolve.py](../../../shared/api/ewa_platform/companion/orchestration/flows/catalog_resolve.py) and [shared/api/ewa_platform/companion/orchestration/tools/handlers_files.py](../../../shared/api/ewa_platform/companion/orchestration/tools/handlers_files.py).

EwaFile is registered as a system desktop folder. Task folders are ordinary children created by the folder service. The legacy [backfill SQL](../../../shared/api/migrations/applied/20260524_ewa_companion_folder_backfill.sql) moves nondeleted rows with matching companion source/tag/metadata to the root, including rows in another folder; inspecting that migration does not prove it was applied or authorize rerunning it.

## Tool entry points and observable results

File handlers are registered in [shared/api/ewa_platform/companion/orchestration/tools/handlers_files.py](../../../shared/api/ewa_platform/companion/orchestration/tools/handlers_files.py); `catalog_list` belongs to [shared/api/ewa_platform/companion/orchestration/tools/handlers_desktop.py](../../../shared/api/ewa_platform/companion/orchestration/tools/handlers_desktop.py). The public registry is a re-export; patch the module where a function resolves its dependencies when testing.

- `catalog_list`: browse/search shortlist, appendix, compact hits and embedded file-list output surface. Successful output has no desktop action by default. Forced workflow browse can return an unavailable/empty reply and an EwaFileManager open action; ordinary unavailable paths may return None. A bypassed `file_open` without a query/id delegates here.
- `file_open`: named, explicit-id or newest-focus selection; returns a DocEditor action, document-editor surface and id/label data. Focus persistence is best effort. This result does not certify that the editor loaded a readable body.
- `catalog_discuss`: owner body projection into memory_append, followed by the main model. Format/cap/failure boundaries are in its dedicated guide.
- `file_create`: resolve literal/generative inputs, compose if needed, select folder, then immediate auto-accept write or an awaiting-confirmation task. A bare request without body/topic can return an informational reply; it is not a created file.
- `file_save_text`: workflow-only bypass with explicit name and body/text, clipped to 240000 characters; uses the same create/auto-accept path.
- `file_rename` / `file_delete`: build saved plans and awaiting-confirmation runs after target resolution and available permission checks. Their normal handlers require the companion pool.
- `doc_insert`: prepare a complete editor body from stored source/target bytes, then await confirmation; confirmation emits an editor action rather than writing Unified Content directly.
- `file_rewrite`: immediate server-first owner rewrite when its feature and full-replacement intent match; no companion confirmation task is created by this path. `mode=append` uses attributable blocks instead.
- `doc_append_block`: immediate owner block mutation with a freshly read expected version. Explicit id must parse as UUID; named resolution uses the catalog picker. Conflict returns status error and version-conflict data.

The common flow adapter reports needs_open_editor for that condition, needs_confirm whenever a task_run exists, and otherwise ok. A terminal response or status ok can be a denial/not-found/informational reply; inspect the action, task state and operation-specific result. Exceptions outside a handler's local catches reach the registry's error mapping. None means routing fallthrough.

## Catalog listing and target selection

`catalog_list` optional folder_item_id accepts `ewa_file` or a task prefix; an invalid value is ignored and falls back to the root scope. Folder label lookup can return no match, also widening to root. It does not promise an empty result for a nonexistent requested folder. Successful data includes catalog_appendix, row_count, catalog_hits (up to ten compact rows), orchestration_branch and folder_item_id; the bundle controls the actual shortlist/appendix bounds and output surface.

Named create reuse differs from the ordinary fuzzy picker. [Catalog pipeline](../../../shared/api/ewa_platform/companion/storage/catalog_pipeline.py) searches up to 80 compact rows with the supplied name, then up to 120 recent rows, over the whole owner EwaFile/task scope. It compares casefolded name, original_filename and title and accepts the first exact match. This is bounded application deduplication, not a DB uniqueness guarantee; truncated result pages and concurrent creates can escape it.

The named read/rewrite picker uses variant searches and document-like preferences. Rename/delete's phrase resolver uses up to twenty hybrid compact rows per variant and carries row permission flags; missing flags default to true. These pickers do not guarantee unambiguous exact-name resolution for every catalog.

## Create, reuse and folders

New filenames are stripped of surrounding quotes, defaulted when blank and given `.md` unless the extension is md/txt/html. The final 255-character clip can cut a long extension. Natural doc-create defaults use up to two topic words plus a UTC minute stamp; the filename timestamp ContextVar can retain a supplied time within its context. Structured name/body inputs can bypass natural-language matching. Literal plans clip bodies to 240000 characters.

An exact-name hit is resolved **before** the requested destination folder. The pipeline calls replace_file_content on that existing id, preserving snapshots by default, then marks deduplicated_reused on model-copy results. It does not move the row or pass expected_version. A create request targeting a new task folder can therefore overwrite an existing same-name row in another task folder and return that old location. DOC-CODE-066 records the mocked reproduction; the earlier editor-save issue has a separate caller. Without a hit, create_content receives private document metadata, companion source/tags and the selected folder.

Folder intent defaults to EwaFile root. `_agentic_session_id` does not become a task folder automatically. Explicit task keys or create_folder/new-folder intent create/reuse `ewa-task-<key>`; named keys use the first sixteen hex characters of SHA-1 over the cleaned casefolded label. Human labels stay stable for named folders; legacy labels can include a UTC stamp. Source: [shared/api/ewa_platform/companion/orchestration/companion_folder_intent.py](../../../shared/api/ewa_platform/companion/orchestration/companion_folder_intent.py), [shared/api/utils/ewa_task_folder.py](../../../shared/api/utils/ewa_task_folder.py) and [shared/api/services/ewa_task_folder_service.py](../../../shared/api/services/ewa_task_folder_service.py).

Natural reuse lookup scores exact/stamp-stripped/substring labels and returns the first best match; it is not an ambiguity gate. Missing label reuse falls back to idempotent named creation. Explicit folder_item_id in create intent is accepted without validating its prefix/tree/existence there, unlike catalog-list's prefix filter. Existing task ids are reused; service failures can return None and cause root fallback. These are not guarantees that every requested folder is successfully selected.

Handlers resolve/create the folder before the file's confirmation task. Cancelling the subsequent file proposal therefore does not imply no desktop folder was created. Auto-accept creation requires the exact boolean `_auto_accept_hitl=True` and writes through main storage directly, returning id/name/reuse metadata plus a companion-only DocEditor action without an awaiting run. Agentic policy/preference may set that flag or finalize a residual pending gate; its broader scheduler/authorization contract is not accepted here. Source: [shared/api/ewa_platform/agentic/auto_accept_hitl.py](../../../shared/api/ewa_platform/agentic/auto_accept_hitl.py).

## Generative document composition

[Doc-create flow](../../../shared/api/ewa_platform/companion/orchestration/flows/doc_create.py) composes before preparing the normal confirmation task. It uses persona seed and, when available, six recent episodic snippets clipped to 400 characters. A failed memory lookup degrades without those snippets. Generation is a sidecar HTTP completion; no source inspection proves factual quality or provider availability.

Scale markers select long before brief, otherwise standard. Defaults/limits are character counts:

- brief: target 400–3500, at most two passes, soft acceptance floor 200;
- standard: target 1200–12000, at most three passes, soft acceptance floor 400;
- long: default target 24000–48000, up to four passes, minimum required before success. Configured max is clamped to 4000–48000, then the long branch floors it at 24000; minimum is bounded and floored at 8000. Settings catalog's supported max range is 24000–48000.

MAX_PASSES clamps to 1–6. NUM_PREDICT defaults to 16384 and clamps to 2048–65536. NUM_CTX defaults through companion context to 262144 and uses the compatibility cap; nonpositive values omit it. TIMEOUT_SEC defaults to 90 and clamps to 20–300 per HTTP pass; deep mode floors it at 180. These are not a total task wall-clock budget. Settings values/catalog defaults are source metadata, not deployed effective values; see [settings](EWA-PLATFORM-SETTINGS-DB.md).

Deep mode is chosen only when enabled and the line contains document/research markers or is long; missing deep URL falls back to the interactive runtime. Model settings follow the doc-create runtime's precedence, with deep-model override when selected. Continuations strip outer fences, ignore chunks below eight characters, append/clip to target_max, and stop at target_min or a usable brief/standard stop response. A sliced agentic call can return status continue and doc_create_draft_v1; fingerprint of line/name controls reuse. That intermediate result is not a saved document.

[Agentic context enrichment](../../../shared/api/ewa_platform/agentic/kernel/tool_args_enrich.py) places Document request before clipped Research context, using up to 48000 context characters by default (8000–64000 clamp for file_create). Literal bodies remain separate. The current locale/scale parser takes all text after Document request, including research; any Cyrillic anywhere can force Russian and research long markers can override a brief English ask. This contradicts request-language/scale precedence comments; DOC-CODE-068 records the bounded prompt reproduction. Do not promise the requested language/length is preserved in mixed-language research input.

## Confirmation and mutating storage

[Task confirmation](../../../shared/api/ewa_platform/companion/orchestration/task_run_confirm.py) assumes the caller already verified principal/status. It claims confirming/running with a task revision before executing. A claim mismatch returns revision_conflict without mutation. Successful claim, file mutation, step updates and final task update are separate operations; a final revision conflict does not roll back a file effect. The saved plan is authoritative for confirmation, and the task revision is distinct from unified_content.version.

For doc_create, confirmation calls the same name-reuse pipeline. Rename calls update_content with the saved id/name; delete calls get_content then delete_content. Owner delete sets deleted_at; a permitted non-owner delete leaves a shared library via ShareService. Generic [delete storage](../../../shared/api/services/unified_content/content_storage_delete.py) also has a separately verified platform-admin option, which this companion caller does not pass. Search/vector cleanup is best effort. No restore/reindex success or live recipient scope is accepted by the mocked proposal tests.

For doc_insert, source resolution excludes the target id. Both bodies are fully owner-read, decoded as UTF-8 with replacement and checked only for a NUL prefix, without a read byte cap. Source text is escaped/clipped to 120000 characters; target plain text is escaped/clipped to 180000, while an HTML-looking target is retained before adding a separator/header/source. The saved full body is emitted on confirm without target version or current buffer revalidation. Client consumer checks matching content id and rejects collaboration, then normalizes/updates editor content without a dirty-state/version guard. Unsaved/intervening changes are therefore not protected by this proposal contract; DOC-CODE-069 records the server body probe and client source boundary. Source: [shared/api/ewa_platform/companion/orchestration/flows/doc_insert.py](../../../shared/api/ewa_platform/companion/orchestration/flows/doc_insert.py) and [shared/web/frontend/src/components/UltimateDocEditor/hooks/useUltimateDocEditorInnerContentCompose.ts](../../../shared/web/frontend/src/components/UltimateDocEditor/hooks/useUltimateDocEditorInnerContentCompose.ts).

## Rewrite, snapshots and optimistic locks

[Server-first v2](../../../shared/api/ewa_platform/companion/server_first/v2.py) selects an owner row, or can create a missing named md/txt/html placeholder before generation. A preexisting exact-name hit is reused. Failed generation can leave that newly created placeholder. It reads version before the model and passes expected_version to replace/append. Storage conflicts produce a retry reply. Download-size rejection happens after full owner retrieval; UTF-8/NUL checks are text heuristics, not general document extraction.

[Storage replacement](../../../shared/api/services/unified_content/content_storage_service.py) checks owner and optional version preflight, quota delta and hash. With preserve_version=True, a changed hash triggers [VersionManager](../../../shared/api/services/unified_content/version_manager.py) snapshot before overwrite; unchanged hash need not snapshot. Failure to create the snapshot propagates before byte replacement. Existing tests check ordering and preflight/conditional-update conflicts. A snapshot is a separate storage/DB operation, not a complete atomic rollback guarantee.

PostgreSQL byte storage receives the mutation transaction's connection. External replacement deletes the old object and stores the new one before the conditional metadata update. UPDATE 0 raises a version conflict, but a PostgreSQL rollback cannot restore those external operations. DOC-CODE-067 reproduces old-object removal/new-object persistence with synthetic external storage and a conflicting update. A snapshot may aid recovery when enabled, but does not make the operation atomic; this probe disabled snapshots to isolate ordering. Do not describe all writes as non-destructive or safely rolled back.

Version increment is not implemented by explicit +1 in replace_file_content. The repository includes [versioning SQL](../../../shared/api/migrations/fix_functions_and_triggers.sql) that reacts to name/extracted_text changes; this guide does not certify the installed trigger or binary-only/version-history parity. General version restore, retention, concurrent snapshot numbering and all backend switches remain separate storage acceptance.

Block append/patch/remove use an owner/version preflight plus FOR UPDATE row version and conditional metadata update before text-byte sync. They preserve unrelated blocks in the logical mutation, while their rendered bytes/storage are regenerated. Their complete multi-backend/quota/version-history behavior is not accepted by the rewrite ordering tests.

## Client surfaces and mission documents

The action dispatcher opens a content-id DocEditor in the companion by default; open_on_desk enables desktop opening too. Set-body uses desktop event fanout and a registered editor consumer. Action delivery is not evidence of successful content load/persistence. Source: [shared/web/frontend/src/features/ewa/companionUx/useCompanionActionDispatch.ts](../../../shared/web/frontend/src/features/ewa/companionUx/useCompanionActionDispatch.ts) and [shared/web/frontend/src/pages/Desktop/utils/desktopDeepLink.ts](../../../shared/web/frontend/src/pages/Desktop/utils/desktopDeepLink.ts).

Created-document trace fallback accepts confirmed HITL gate events and successful file_create/file_save_text act rows, deduplicating nonempty ids. The mission tree selects the latest act summary/id and offers document opening when an id/callback exists, with document-list fallbacks. Neither helper establishes successful generation, trace persistence, provider work or a loaded editor. Source: [shared/web/frontend/src/features/ewa/agentic/agenticCreatedDocumentsFromTrace.ts](../../../shared/web/frontend/src/features/ewa/agentic/agenticCreatedDocumentsFromTrace.ts), [shared/web/frontend/src/features/ewa/agentic/AgenticTaskTreePanel.tsx](../../../shared/web/frontend/src/features/ewa/agentic/AgenticTaskTreePanel.tsx) and [shared/api/ewa_platform/agentic/adapters/task_run_mirror.py](../../../shared/api/ewa_platform/agentic/adapters/task_run_mirror.py).

File-focus/file-study lyrics/audio deferral and TurnPlan have narrower heuristics and known persistence limits; use the multi-intent guide instead of assuming every analysis reads successfully or every audio branch is blocked. General library sharing belongs to [Content Manager](../CONTENT-MANAGER.md); editor collaboration/save/restore belongs to [editor and shell context](EWA-COMPANION-DOC-EDITOR-AND-SHELL-CONTEXT.md), whose independent audit remains pending.
