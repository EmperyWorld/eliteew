# P1 — Что такое EliteEW

**Схема:** [D01](../assets/diagrams/D01-hybrid-formula.md)

## Формула

**EliteEW** — рабочая среда организации: стол с приложениями, файлы и документы,
проекты на своих данных, связь внутри контура и ИИ на материалах организации.

Это **управляемый рабочий слой** поверх обычного устройства: рабочие приложения
и файлы живут в продукте, а не как «просто папки на личном столе».  
Это **не** замена хост-ОС и **не** обещание стерильного диска.

Параллельно это **дар миру**: first-party код открыт по `MIT` —
можно принять, изучить, изменить и распространять на условиях лицензии
([P3c](03c-full-complex-source.md)). Свобода кода ≠ штат авторов и ≠ услуги.

## Хост / DIY / EliteEW

| Ось | Хост | DIY | EliteEW |
|-----|------|-----|---------|
| Роль | Привычный ПК / сервер | Самосборный стек | Рабочий слой поверх хоста |
| Сильнее здесь | Драйверы, локальный софт | Гибкость сборки | Единый стол, apps, файлы, роли, периметр сессии |
| Чего нет | — | — | Замены ядра ОС «на любом edition» |

## Кому это

Тем, кому нужен **свой** контур работы, а не зоопарк внешних сервисов — и кто
готов принять открытый комплекс. Как пользоваться даром — [P3e](03e-delivery-models.md);
editions — [P10](10-editions.md); apps — [P6](06-app-index-brief.md) / [P11](11-must-app-cards.md).

# P1a — Доступ с любого устройства, в т.ч. иммерсивные дисплеи

**Детали звонков/GAF:** P7a / P7b (здесь только any-device + иммерсивные дисплеи)  
**Mobile subset:** P7e · **Desktop-клиент:** P8

## Тезис

EliteEW открывается там, где есть современный **браузерный** контур — ПК, ноутбук,
планшет в браузере, Android-спутник, а также **иммерсивный шлем** (VR / XR)
через браузер шлема.

Отдельного «VR-приложения в магазине шлема» продукт **не** выпускает.
На шлеме — тот же **веб-слой**: стол, apps и внутренние видеозвонки
(в т.ч. из GAF Chat), когда браузер, микрофон и камера шлема пригодны к работе.

**Проверено:** сценарий на шлеме проверен; **модель шлема в публичном
тексте не называется**.

## Карта устройств

| Контур | Что получаете | Не это |
|--------|---------------|--------|
| Браузер (ПК / ноутбук / планшет) | Полный рабочий слой в браузере | Замена хост-ОС |
| Android-спутник | Подмножество лента / чат / push ([P7e](07e-mobile-capability-matrix.md)) | Полный стол как на desktop |
| Браузер иммерсивного шлема | Веб-слой + внутренние звонки при годном железе | Нативный VR-OS · магазин шлема · «любой шлем без браузера/мика/камеры» |
| Tauri desktop-клиент | Connected-клиент ([P8](08-tauri-clients-ota.md)) | Второе продуктовое дерево |

## Честная рамка

| | |
|--|--|
| **Есть** | Браузерный доступ · Android-спутник · звонки — веб/WebRTC-контур · шлем проверен без имени модели |
| **Проверено** | Путь браузера шлема к веб-UI продукта и внутренним звонкам |
| **Не обещаем** | Нативный VR-OS · листинг в магазине шлема · «любой шлем офлайн без браузера» · телефон = полный EliteEW |

Сравнение «хост / DIY / EliteEW» — кратко в [P1](01-what-is-eliteew.md); границы обещаний — [P12](12-honest-limits.md).

# P2 — Угрозы и защита

**Схема:** [D02 — классы угроз](../assets/diagrams/D02-threat-classes.md)

## Проблема (не люди — канал)

Массовый канал утечки mid-market: личные мессенджеры, личные облака, копипаст в внешний AI. VPN закрывает «трубу», но не видит содержимое личного приложения. Классический DLP часто требует агента на endpoint — на BYOD это ломается юридически и социально.

EliteEW — **быстрый рычаг** поверх текущего стека ИБ: разделение рабочего и личного контура. **Не** замена firewall / антивируса / полного DLP-стека.

## Классы угроз → ответ продукта

| Класс | Что происходит | Ответ EliteEW |
|-------|----------------|---------------|
| Shadow IT / личный мессенджер | Рабочие файлы уходят в личный канал | Рабочий чат/файлы внутри контура (P7a) |
| Личные облака | Копия вне контроля организации | Файлы в управляемой библиотеке (P4a) |
| Копипаст / внешний AI | Фрагменты во внешний чат | ИИ и материалы — в контуре проекта (P5b) |
| BYOD без разделения | Личная ОС = рабочий стол | Браузерный / APK слой без admin-агента на личной ОС |
| MITM / открытый доступ | Сервисы «на всех» | Edge / доверенный доступ (P7d) |
| Недоверенное устройство / OTA | Подмена клиента | Trust-границы клиентов (P8) |
| Insider / роли | Лишние права | Роли org/проекта (P5a) |
| Фото экрана | Аналоговый канал | Минимизация цифрового канала — не 100% (P12) |
| «Стерильный диск на всех edition» | Нет следов на личном диске | Не универсальное обещание (P12) |

Сравнение «хост / DIY / EliteEW» — кратко в [P1](01-what-is-eliteew.md); границы обещаний — [P12](12-honest-limits.md).

# P3 — Карта нормативных ориентиров

**Схема:** [D03 — нормы: даёт / остаётся](../assets/diagrams/D03-npa-split.md)

## Важно

Текст — **карта ориентиров** для диалога ИБ и юристов организации. EliteEW **помогает** закрыть организационно-технический контур (разделение данных, доступ, роли, периметр). Это **не** замена аттестации, лицензирования средств защиты, оценки воздействия и внутренних политик.

**Запрещено в этом пакете:** заявления об «уже аттестовано», «полное соответствие закону из коробки», гарантии штрафов/исков.

Актуальные формулировки норм организация сверяет со своими юристами.

## Ориентиры (смысловая карта)

| Ориентир | О чём речь | Что даёт EliteEW | Что остаётся организации |
|-----|------|-----|---------|
| Требования к защите информации / ЗИ | Контур и доступ | Управляемый периметр, роли, контроль доступа к рабочему слою | Модель угроз, аттестация, выбор СЗИ, оргмеры |
| Трансграничная передача данных | Куда уходят персональные данные | Хранение и работа в **выбранном** edition-контуре (cloud / on-prem) | Юр. основания, договоры, реестры |
| Применение ИИ | Прозрачность и контроль | ИИ на данных проекта внутри контура; политики доступа (P5b) | Политика ИИ, оценка рисков, ответственность оператора |
| Персональные данные | Защита и разделение | Технические рычаги разделения и доступа | Оператор данных, согласия, локализация по модели |

Точные статьи и даты — в legal pack организации; здесь только **смысл**.

# P3a — День сотрудника: внутреннее внедрение

**Схема:** [D04 — день сотрудника](../assets/diagrams/D04-employee-day.md)  
**НПА:** только ссылка на [P3](03-regulatory-map.md) — без пересказа

## Позиция

EliteEW — не «ещё один SaaS сбоку», а **единый контур рабочего дня** сотрудника организации: стол, файлы, документы, общение, ИИ на материалах проекта, мобильный спутник — с ролями и периметром.

## Один день (swimlane)

1. **Вход** — единый вход в рабочий слой (детали SSO — P5c).  
2. **Стол** — окна, магазин приложений под роль (P4, P5, P6).  
3. **Файлы и документы** — библиотека, ACL/vault, редактор (P4a–b).  
4. **Связь** — внутренний мессенджер и видеозвонки (P7a–b); при необходимости — телефон/VR (P1a, P7).  
5. **Маркетинг / проект** — кабинет на данных проекта (если роль) (P5 / Must cards).  
6. **ИИ** — в контуре, не «в личный внешний чат» (P5b).  
7. **Мобильный** — лента/чат/push как спутник, не полный стол (P7e).

Угрозы и agentless — в [P2](02-threats-and-protection.md) / [P2a](02a-agentless-instant-access.md); здесь не повторяем.

# P3c — Комплекс, открытый код, дар миру

## Суть

EliteEW отдаётся миру как **свободное ПО**: first-party код по умолчанию —
`MIT` (корневой `LICENSE` репозитория). Это про **свободу**,
про свободу пользоваться и делиться кодом.

1. **Комплекс** — не «один чат» и не «один диск»: стол, apps, файлы, связь, ИИ,
   мобильный спутник, editions (cloud / on-prem / client) в одной платформе.
2. **Свой экземпляр** — развёрнутый контур организации остаётся **её** контуром
   (особенно on-prem), а не общей демо-учёткой.
3. **Свободный исходный код** — можно запускать, изучать, изменять и
   распространять first-party код на условиях MIT. Публичный ориентир исходников
   : [github.com/EmperyWorld/eliteew](https://github.com/EmperyWorld/eliteew)
   (см. также карту лицензий в каноне платформы).
4. **Условия MIT** — сохраняйте уведомления об авторских правах и текст
   разрешения в копиях или существенных частях ПО. MIT не требует публикации
   изменений или исходников сетевого сервиса.
5. **Не весь tree одной лицензией** — first-party default = MIT;
   явные лицензии компонентов и third-party — по своим SPDX / NOTICE / SBOM.
   Карта: `documentation/platform/THIRD-PARTY-LICENSE-MAP.md`.

## Что это не отменяет

Имя и логотип EliteEW — не «часть MIT». Форк и доработка — по лицензии кода;
называть форк официальным EliteEW без отдельной договорённости о знаке — нельзя.

Как жить с даром на практике — [P3e](03e-delivery-models.md).
Как принять артефакты релиза у себя — [P3f](03f-transfer-bom-handover.md).

# P3d — Структура затрат self-host (ориентир)

**Схема:** [D09](../assets/diagrams/D09-tco-columns.md)

## Дисклеймер

Ниже — **структура** статей, если организация ведёт контур **сама**.
Это не тариф и не условие услуг, не оценка дара в деньгах и не ROI-формула. Дар по MIT —
про свободу кода; затраты появляются у хоста, людей и эксплуатации.

## База статей

| Статья | Типичный десктоп-контур | Self-host DIY | EliteEW self-host |
|--------|-------------------------|---------------|-------------------|
| Хост-ОС / устройства | Лицензии / обновления ПК | Железо + поддержка ОС | Хост остаётся; слой — профиль контура |
| Агентный DLP/EDR на BYOD | Лицензии + конфликты | Аналогично | Не требуем admin-агент на личной ОС (P2a) |
| Зоопарк внешних сервисов | Много подписок | Self-host + ФОТ | Единый контур apps |
| Подъём контура | Долгий агентный путь | Долгая сборка | После выдачи доступа — минуты–дни (ориентир) |
| Поддержка | Helpdesk агентов/ПО | Высокий ФОТ DIY | Ваша служба / SI |
| Риск Shadow IT | Высокий без слоя | Высокий без слоя | Слой разделения (P2) — не нулевой риск |

## Как читать

«Дар» не обнуляет ФОТ. Смысл — меньше зоопарка и агентного конфликта BYOD,
**если** сценарии реально сводятся в EliteEW. Конкретные цифры — вне пакета.

| Ось | Хост | DIY | EliteEW |
|-----|------|-----|---------|
| Драйвер затрат | ОС + агенты + SaaS | ФОТ сборки | Хост + люди на контур |
| Ловушка | Shadow IT | «Бесплатно» ≠ дёшево в ФОТ | Нужна дисциплина ролей |

# P3e — Дар миру: как пользоваться открытым комплексом

**Схема:** [D11](assets/diagrams/D11-gift-to-world.md)<br>
**Не путать с:** обязательным платным контуром · аттестатом · закрытой передачей исходников вне MIT

## Центр

EliteEW — **дар миру** в форме свободного ПО. Главный путь — взять first-party
код по `MIT`, развернуть свой контур и развивать его.
Свобода кода ≠ «в комплекте штат авторов, SLA и официальный бренд».

| Путь | Что это |
|------|---------|
| **Self-hosted по MIT** | Запуск, изучение, изменение, распространение first-party кода; без платы за «право открыть репозиторий» |
| **Свой on-prem / изолированный контур** | Тот же дар, развёрнутый у организации (ИТ или SI) |
| **Hosted / сопровождение (опция)** | Кто-то может помочь эксплуатировать или принять релиз — это **сопровождение**, не замена MIT и исходники остаются открытыми по MIT |
| **Имя и знак** | MIT не передаёт права на бренд EliteEW; свой бренд поверх продукта — отдельная тема о знаке |

## Зачем организации открытый контур

1. **Свой рабочий периметр** — стол, файлы, связь, роли, мобильный спутник.
2. **Контроль данных** там, где нужен свой контур ([P3](03-regulatory-map.md)).
3. **Один день сотрудника** ([P3a](03a-employee-day-adoption.md)).
4. **Отраслевой акцент** без второго продукта ([P3b](03b-industry-profiles.md)).
5. **ИИ на своих материалах** ([P5b](05b-generation-spend-vault-ai.md)).
6. **Доступ к hosted-каналу** (если пользуетесь) **не отменяет** право self-host
   ([P9](09-capsules-enterprise-seats.md) · [P9a](09a-controlled-licenses-sealed.md)).
7. **Свободный код комплекса** ([P3c](03c-full-complex-source.md)).

## Что можно сделать

| Шаг | Смысл | Куда |
|-----|--------|------|
| Принять дар | Развернуть first-party код у себя | P3c · P10 |
| Свести Shadow IT | Рабочие чат/диск/ВКС/ИИ — в контуре | P2 · P2a · P7* |
| Собрать on-prem | Свой экземпляр edition | P10 · P10b |
| Попросить сопровождение | Опционально: помощь с приёмкой/эксплуатацией | P3f · P3g |
| Развивать вертикаль | Профиль apps + роли на свободном коде | P3b · P5a · P11 |
| Без user-CLI | Ops у ИТ/SI организации | P10c · P12 |

Дальше: артефакты и приёмка у себя — [P3f](03f-transfer-bom-handover.md);
миграция — [P3g](03g-si-migration-playbook.md); вопросы — [DD](13-onepager-dd-rfi.md).

# P3f — Принять дар у себя (артефакты · Day‑0…90)

**Схема:** [D12](../assets/diagrams/D12-transfer-handover.md)  
**Дар и лицензия:** [P3c](03c-full-complex-source.md) · **как пользоваться:** [P3e](03e-delivery-models.md)  
**Не путать с:** ops-runbook оператора · user-CLI · «секреты чужого контура в zip»

## Зачем глава

Код уже открыт по MIT. Организации нужен практический ответ: **какие артефакты
сверять**, чего в «передаче контура» не будет, и как за первые недели поднять
свой экземпляр без иллюзии, что «дар» = бессрочный штат авторов.

## Классы артефактов (не секретный манифест)

Ниже — ориентир для due diligence self-host / on-prem. Право пользоваться
first-party кодом по MIT от этого списка **не зависит**.

| Класс | Обычно есть | Обычно нет |
|-------|-------------|------------|
| Исходники | Публичный MIT source + commit/tag релиза | Чужие SaaS-аккаунты, чужие ПДн, чужие ключи |
| Документация | Актуальный product/platform-канон для развития | Внутренние черновики, agent-диалекты |
| Сборка | Рецепты сборки, тестовые контуры без prod-секретов | Пароли, ключи хостов, боевые SOPS-бандлы |
| Конфиг-образец | Scrubbed шаблоны / профили edition | Боевые URL/IP, client id чужого IdP |
| Клиенты | Исходники / артефакты Desktop / mobile по согласованному объёму | Чужие сертификаты магазинов без отдельной передачи |
| Знания | Согласованный объём передачи знаний — **если** договорились о сопровождении | Обещание «авторы навсегда» |
| Бренд | Только если отдельно согласован знак | Автоматическое право выдавать fork за официальный EliteEW |

**Права:** first-party default — `MIT`; явные лицензии компонентов и
third-party — по своим лицензиям (карта third-party + SBOM релиза). Знак и
имя — отдельно. Этот пакет **не** юридическое заключение.

## Логика «дня принятия»

1. Ссылка на публичный source и точный commit/tag (+ согласованные бинарные артефакты, если нужны).
2. Чеклист классов выше (не user-CLI).
3. Если есть сопровождение — контакт на период приёмки (не «вечный user support»).
4. Архитектор / наставник внедрения — **только** если отдельно договорились ([P3e](03e-delivery-models.md)).

## Ориентир Day‑0…90

Сроки зависят от зрелости ИТ/SI и edition. Цифры — ориентир, не договорный SLA.

| Фаза | Ориентир | Фокус | Результат |
|------|----------|-------|-----------|
| **H0 Сверка артефактов** | Day 0–14 | Source, commit/tag, сборки, docs | «То, что нужно для своего стенда — на месте» |
| **H1 Первый стенд** | Day 14–45 | Свой экземпляр, IdP, smoke ролей | Живой стенд **у вас** |
| **H2 Пилот** | Day 30–75 | Отдел: стол, файлы, чат, роли ([P3a](03a-employee-day-adoption.md)) | Доказанный день сотрудника |
| **H3 Масштаб** | Day 60–90+ | Runbooks вашей службы ([P10c](10c-ops-scale-not-user-cli.md)) | Ops без пользовательского CLI |
| **H4 Закрепление** | по плану организации | Критерии edition + нужные apps | Контур живёт у вас |

Миграция с зоопарка — [P3g](03g-si-migration-playbook.md).

## Риски (сжато)

| Риск | Смысл | Опора |
|------|--------|-------|
| Нет штата авторов «в даре» | Развитие — ваши / SI | P3e · P3g · P12 |
| Key-person | Не default | Только отдельная договорённость |

| Third-party лицензии | Чужой код | SBOM + NOTICE + карта third-party |
| Чужие prod-секреты | Не часть дара | Не включать; scrub |

# P3g — SI, миграция с зоопарка, PoC до масштаба

**Связь:** [P3f приёмка](03f-transfer-bom-handover.md) · [P3e сервисная модель](03e-delivery-models.md) · [P3a день](03a-employee-day-adoption.md)

## Роль SI (self-managed сценарий)

| Зона | SI / ИТ организации | Не считать частью лицензии на код |
|------|--------------------|--------------------------------------|
| Host / сеть / резерв / мониторинг | Да | Постоянный ops-штат авторов |
| IdP, роли, offboarding | Да (с ИБ) | «Включили и забыли» |
| Первый стенд edition | Да | Готовый managed prod как ваш self-hosted контур |

| Архитектор Empery | Только отдельный договор | Гарантия «возглавит» |

## Состав команды внедрения (ориентир)

| Роль | Зачем | Комментарий |
|------|-------|-------------|
| Владелец внедрения (организация) | Приоритеты, acceptance | Нельзя «отдать SI без спонсора» |
| Архитектор платформы | Edition, IdP, границы контура | Может быть ваш / SI; архитектор Empery — отдельная услуга |
| ИБ | Политики, edge, managed service entitlements | CISO-path: P2 → P7d → P8a → P9a |
| Desktop / client | Tauri / FoFline контур | P8 · P10a |
| Mobile (если в scope) | Спутник, доверенные устройства | P7 · P7e |
| Данные / файлы | PG + object store, ACL | P4a · P4b |
| Change / обучение | День сотрудника | P3a |

## Миграция с зоопарка (программа, не «кнопка»)

Типичный старт крупного организация: почта/чат снаружи, диск снаружи, ВКС снаружи, ИИ в личных аккаунтах. EliteEW **не** обещает мгновенную замену всего Microsoft/Google стека ОС.

| Волна | Смысл | Опора |
|-------|--------|------|
| M0 Карта Shadow IT | Что реально используют (чат/диск/ИИ) | P2 |
| M1 Контур дня | Стол + файлы + роли для пилотной группы | P4 · P4a · P5a · P3a |
| M2 Связь | Внутренний мессенджер / ВКС вместо рабочих переписок снаружи | P7a · P7b |
| M3 ИИ | Генерации и vault на своих материалах вместо личного SaaS | P5 · P5b |
| M4 Mobile / edge | Спутник и доступ по доверию — по необходимости | P7 · P7d |
| M5 Вывод | Политика: рабочие каналы только в контуре | ИБ + орг. приказ; не «магия продукта» |

Честно: параллельный период двух контуров почти всегда нужен; длительность — Discovery, не тарифный ориентир.

## PoC до масштаба (честный)

Цель PoC — подтвердить реальные возможности продукта, не абсолюты из [P12](12-honest-limits.md).

| Проверка | Ожидание | Не ожидать |
|----------|----------|------------|
| Agentless / быстрый доступ | Нет admin-агента на личной ОС как нормы | «Стерильный диск всегда» |
| День пилотной группы | Стол + файлы + роли работают | 1000+ пользователей за неделю |
| Edition on-prem / изолированный | Стенд **у вас** поднимается SI | Чужой shared demo = ваш контур |
| E2EE чат (если в scope) | Opt-in + ключ на телефоне | Все чаты всегда E2EE |
| Atomic native (если Connected/FoFline) | Условие native-клиентов | То же для всего браузерного SPA |
| Latency / UX | Ориентир на PoC | Универсальный ≤200 мс как обещание |
| НПА | Карта «помогает» | Аттестат по защите информации из коробки |

Границы: [P12](12-honest-limits.md). RFI-таблица: [13-onepager-dd-rfi.md](13-onepager-dd-rfi.md).

Сравнение «хост / DIY / EliteEW» — кратко в [P1](01-what-is-eliteew.md); границы обещаний — [P12](12-honest-limits.md).

# P4a — Файлы: метаданные, object store, доступ, поиск

**Схема:** [D05](../assets/diagrams/D05-files-two-planes.md)

## Две плоскости (честно)

| Плоскость | Что хранит | Смысл для пользователя |
|-----------|------------|-------------|
| **PostgreSQL** | Метаданные, версии, ACL, привязка к компании/проекту | «Кто видит файл и в каком проекте он лежит» |
| **Object store (S3-класс; в контуре Empery — SeaweedFS)** | Байты файла | Содержимое не лежит «просто на диске ПК сотрудника» как единственный источник истины |

Пользователь работает через **Файловый менеджер**; в PG/Seaweed руками не ходит.

## Что умеет контур

- Единая библиотека с папками, версиями, шарингом, квотой хранилища  
- Скоуп **компании / проекта** (в т.ч. vault проекта маркетинга)  
- Поиск: по тексту и **умный** (полнотекст + семантика по индексу документов)  
- После извлечения текста / OCR сканов — материал становится находимым в поиске (обработка на стороне платформы; не «магия 100% на любом скане»)

# P5b — Контроль расходов на генерации · ИИ на данных проекта

Тяжёлые генерации (изображения, презентации, музыка и др. через единый контур генераций) учитываются как **энергия / кредиты** типов генерации. В интерфейсе пользователь видит стоимость до запуска; при нехватке — отказ с честным состоянием (не «тихий успех»).

Это **контроль расхода** внутри продукта, не банковский биллинг в этом тексте.

## ИИ на данных проекта (vault RAG)

В маркетинговом контуре исследования и ответы могут опираться на **документы vault проекта** (RAG), а не на «интернет-мозг» по умолчанию для типов `imc_rag_*`. Качество зависит от того, что загружено в vault; слабое покрытие документов честно подсвечивается подсказками.

# P7 — Android-спутник и безопасность

## Тезис

Мобильное приложение Android — **спутник** рабочего контура: лента, мессенджер, друзья, уведомления, профиль, часть генераций и видеозвонков. Это **не** полный рабочий стол и **не** маркетинговый кабинет на телефоне.

Поверх входа организации доступен слой **доверенного устройства** (привязка телефона): ключи генерируются на устройстве; сервер не получает приватные ключи. Без настроенной блокировки экрана доверенная привязка и GAF E2EE не включаются.

Сравнение «хост / DIY / EliteEW» — кратко в [P1](01-what-is-eliteew.md); границы обещаний — [P12](12-honest-limits.md).

# P7a — Внутренний мессенджер (GAF)

## Тезис

**GAF Chat** — внутренний мессенджер 1:1 внутри контура: переписка, файлы, композер. Смысл для Shadow IT — рабочий канал **не** обязан уходить в личный мессенджер ОС.

По умолчанию чат может быть **обычным** (не E2EE). Шифрование конца-в-конец — отдельный режим (P7c), не «все сообщения всегда E2EE».

# P7b — Внутренние видеозвонки

## Тезис

Внутренние видеозвонки — отдельное приложение **Video Calls**; вход в 1:1 часто из GAF. Медиа идёт через внутренний Meet-контур продукта; звонок открывается **внутри** окна продукта (не «просто ссылка в чужой браузер» как единственная норма).

**1:1:** звонящий **не** входит в комнату, пока получатель **не принял** звонок (сначала принять — потом войти). Есть явные статусы (ожидание / активен / пропущен) и доставка входящего на выбранные поверхности.

**Куда принимать звонок:** обе поверхности (по умолчанию) · только рабочий стол · только мобильный — настройка пользователя.

**Групповые:** отдельный сценарий; у организатора правила входа в комнату **другие**, чем у правила принятия 1:1 — не смешивать в один тезис.

**Не обещаем:** «нативная VR-OS телефония»; звонки на VR — через браузерный слой (P1a, проверено).

Сравнение «хост / DIY / EliteEW» — кратко в [P1](01-what-is-eliteew.md); границы обещаний — [P12](12-honest-limits.md).

# P7c — Доверенный телефон и E2EE-ключ на устройстве

## Тезис

При **доверенной привязке** телефона на устройстве могут появиться отдельные семейства ключей:

| Семейство | Зачем | Приватный ключ |
|-----------|--------|----------------|
| Идентичность устройства | Доказать «это тот же телефон» | На телефоне |
| Канал Secure Connection | Доступ в защищённый периметр | На телефоне |
| **GAF E2EE** | Шифрование чата конец-в-конец | На телефоне |

Сервер хранит **публичные** материалы и ciphertext сообщений; **не** восстанавливает утерянный GAF private key. Потеря ключа без переноса = старые E2EE-сообщения нечитаемы с сервера.

**Включение E2EE в чате :** не по умолчанию; нужно взаимное согласие участников и готовность trusted devices с ключами. Пока E2EE активен, обычный plaintext в этот чат не принимается.

**Не обещаем:** «все чаты всегда E2EE» · «сервер держит секрет расшифровки» · «E2EE = тот же ключ, что WireGuard».

Сравнение «хост / DIY / EliteEW» — кратко в [P1](01-what-is-eliteew.md); границы обещаний — [P12](12-honest-limits.md).

# P7d — Edge: глухая стена и один шаг доступа

**Схема:** [D06](../assets/diagrams/D06-edge-wall.md)  
**Без:** IP, портов, имён интерфейсов в публичном тексте

## Тезис

Снаружи контур устроен как **default-deny**: лишние входы для сканера/случайного интернета закрыты («глухая стена»). Рабочий доступ открывается по **выданному доверию** (seat / peer / доверенное устройство) — для пользователя это сводится к **одному осмысленному действию** (импорт доступа / подъём защищённого канала / привязка), а не к «открыли порты миру».

Есть отдельные контуры доверия для **телефона** и для **desktop-client** — не один ключ на всё (см. P7c / P8 / P9a).

**Не обещаем:** air-gap · «невозможно никак пробить» · публикация внутренней топологии.

# P8a — Atomic Conditional Access

**Схема:** [D07](../assets/diagrams/D07-atomic-access.md)

## Инвариант (обзорный язык)

Для **нативных** клиентов Connected и FoFline вход в продукт завязан на связку:

```text
личность подтверждена
  ∧ лицензия активна
  ∧ канал разрешён
  ∧ устройство / доказательство ключа на месте
  ∧ привязка учётки согласована
→ доступ разрешён
```

Отказ — без детального «оракула» наружу (общая формулировка пользователю; детали — в защищённом аудите).

## Честные границы

| В scope atomic (текущая программа) | Вне v1 / отдельно |
|-----------------------------------|-------------------|
| Нативные клиенты Connected и FoFline | Обычный браузерный SPA организации |
| Enforce на cloud contour для этих клиентов | Mobile SSO как единственный фактор |
| Offline-only seat — локальная entitlement без OIDC | «Абсолютная невозможность обхода» |

**Не обещаем:** atomic = замена firewall · atomic уже на каждом HTTP-запросе всех клиентов мира · browser-вход «навсегда убран у всех».

*(Внутренние OIDC client id в публичный текст не выносим.)*

Сравнение «хост / DIY / EliteEW» — кратко в [P1](01-what-is-eliteew.md); границы обещаний — [P12](12-honest-limits.md).

# P9 — Капсулы и доступ к месту

**Граница:** капсула / seat — это **сервисный доступ** к hosted или доверенному
каналу. Она **не** лицензия кода и **не** отменяет MIT-дар self-host.

## Тезис

Если организация пользуется official cloud, управляемым контуром или доверенным
подключением места, доступ выдаётся как **файл доступа (капсула)**: оператор
выпускает, пользователь импортирует — без «магазинной саморегистрации ключа
с витрины». Self-hosted запуск first-party кода по MIT **не** требует капсулы.

Режимы места: **offline** / **cloud** / **both** — без сырых внутренних id в тексте.

Капсула — носитель доверия к месту; **не** E2EE-ключ чата и **не** пароль IdP.

---

# P9a — Сервисный доступ и sealed-материалы

## Тезис

Слово «лицензия» в старых API-именах здесь значит **сервисный entitlement**:
доступ к hosted, managed-функциям или доверенному каналу. Это **не** лицензия
кода MIT и **не** блокирует self-hosted запуск дара.

| Правило | Смысл |
|---------|--------|
| Контроль | Entitlement можно отозвать / ограничить срок / сменить возможности там, где это поддерживается |
| At rest | В хранении — **хэш** / sealed материалы; не «вечный plaintext ключ в БД как норма» |
| Выдача | Секрет доступа может показаться **один раз** при выпуске; дальше — капсула |
| UX | Импорт **sealed** капсулы; не «вставь ключ в блокнот» как основной путь |
| Клиент | Приватные материалы места — в защищённом хранилище ОС, не в JS/логах |

**Не обещаем:** пользователь обязан править conf вручную · сервер хранит чужие
private-ключи чата · капсула = пароль от всех сервисов мира.

# P10 — Editions: cloud / on-prem / client

**Схема:** [D08](../assets/diagrams/D08-editions.md)  
**FoFline:** ≠ air-gap (ниже)

## Три формы одного продукта

| Edition | Кто держит инфраструктуру | Смысл |
|---------|---------------------------|-------|
| **Cloud** | Hosted-контур | Работа в общем hosted-слое (доступ к месту — отдельно от MIT) |
| **On-prem** | Организация | Self-host дара по MIT или контур с опциональным сопровождением |
| **Client** | В основном устройство | Offline-capable subset; remote tools — по allowlist и entitlement |

**Не обещаем:** «on-prem — одна кнопка для любого без профиля».

## FoFline (client-adjacent)

Свободный **локальный** пакет + опциональный защищённый канал к тому же API.
Локальный self-host профиль запускается **без** сервисной капсулы; hosted /
доверенный канал может требовать entitlement. **Не** чистый air-gap.
**Не** второй независимый backend.

Foundation (entitlement, SSO, shell OTA, local Start) — shipped.
Остаточный live-smoke / pack parity не маскируем под «Done» для всего контура.

# P10a — Нативный клиент и гибрид

Поставка — не «только браузер» и не «только контейнеры»:

# P10c — Ops-масштаб: деплой и контроль (не user CLI)

## Тезис

У Empery / оператора контура — **сотни** автоматизаций деплоя, контроля и
обслуживания (порядок **250–300+** скриптов и обёрток). Это ориентир масштаба,
не «тысячи» и не выдуманное круглое число.

Для **сотрудника организации** это значит: восстановление и выкладка — зона
оператора и Admin-панели, **не** «откройте терминал и запустите скрипт деплоя».

В self-hosted / on-prem тот же принцип: ops-масштаб у **ИТ/SI организации**.
В managed enterprise эксплуатацию и участие архитектора можно оформить
отдельной услугой — см. [P3e](03e-delivery-models.md).

Admin на столе — **упрощённая админ-панель** для ответственных организации
(люди, каталог, очереди), не полная замена IdP-админки и не пользовательская
фича дня.

Сравнение «хост / DIY / EliteEW» — кратко в [P1](01-what-is-eliteew.md); границы обещаний — [P12](12-honest-limits.md).

# P12 — Честные лимиты

Чтобы не смешивать дар и абсолюты. Ниже — то, чего **нельзя** обещать «для всех edition сразу».

| Тема | Как говорить | Как не говорить |
|------|--------------|-----------------|
| Стерильный диск / wipe | Политика конкретного edition; проверять на PoC | «Гарантируем стерильный диск везде» |
| Задержки интерфейса | Ориентир комфорта на PoC | «Всегда ≤200 мс у всех» |
| Фото экрана | Минимизация цифрового канала, не 100% | «Снять экран невозможно» |
| FoFline = air-gap | Нет: локальный пакет + канал ([P10](10-editions.md)) | «Полный air-gap» |
| Замена firewall / AV / DLP | Слой поверх стека ([P2](02-threats-and-protection.md)) | «Заменим весь ИБ-стек» |
| ИИ вместо эксперта | Ускоряет черновики на ваших данных | «Заменит команду» |
| Несколько «студий песен» | Сейчас: **MusicForge** (+ плеер) | Несколько равноправных активных студий |
| Телефон = полный стол | Подмножество ([P7e](07e-mobile-capability-matrix.md)) | «Весь EliteEW в кармане» |
| Всегда E2EE | По согласию ([P7c](07c-trusted-phone-e2ee.md)) | «Всегда E2EE» |
| Затраты self-host | Ориентир ФОТ/хоста ([P3d](03d-tco-orientative.md)) | «Дар = ноль затрат навсегда» |
| Сторонний мессенджер как вход | Не штатный канал ([P10d](10d-external-messenger-honesty.md)) | «Это наш основной вход» |
| Аттестация «из коробки» | Запрещено ([P3](03-regulatory-map.md)) | «Уже аттестовано» |
| Штат авторов «в даре» | Нет ([P3e](03e-delivery-models.md)) | «Авторы ведут вас годами» |
| MIT = весь monorepo | First-party default; исключения и third-party отдельно ([P3c](03c-full-complex-source.md)) | «Всё в репо — одна лицензия» |
| Hosted «для всех завтра» | Опциональный контур, не следствие MIT | «Бесплатная managed-эксплуатация вместе с кодом» |
| Бренд на любом форке | Знак отдельно от MIT | «Форк = официальный EliteEW» |

Возможности рабочего слоя эта глава **не отменяет** — только ограничивает абсолюты.

# Обзор: дар миру и свой контур

Короткая страница для тех, кто решает, **принимать ли EliteEW** в организацию
как открытый рабочий комплекс.

## Что это

**EliteEW** = рабочий стол организации (приложения, файлы, проекты, ИИ на своих данных)  
**+** закрытый рабочий слой (личное и рабочее разделены)  
**+** first-party код как **дар миру** по MIT.

Не замена хост-ОС. Не «100% защита». Не аттестат. Не «принятие дара закрепляет штат авторов навсегда».

Формула — [P1](01-what-is-eliteew.md); лицензия и условия лицензии — [P3c](03c-full-complex-source.md);
границы — [P12](12-honest-limits.md).

## В одном абзаце

EliteEW добавляет **рабочий слой** поверх личного устройства: файлы и приложения организации — в контуре, без системного агента на личной ОС как нормы. Снаружи — закрытый периметр и доступ по выданному доверию. У нативных Connected/FoFline-клиентов доступ завязан на личность, сервисный entitlement, канал и устройство (не универсально для всего браузера). # Глоссарий

| Термин | Смысл |
|--------|-------|
| **EliteEW** | Рабочая среда (стол, apps, файлы, связь, ИИ) + управляемый слой; не замена хост-ОС |
| **Дар миру** | First-party код отдаётся как свободное ПО по MIT |
| **MIT** | Разрешительная лицензия: использование, изменение и распространение с сохранением copyright и текста разрешения |
| **Corresponding source** | Исходники той версии, которую предлагаете пользователям изменённого сетевого сервиса |
| **First-party** | Код авторов EliteEW без более узкой лицензии на файле; default MIT |
| **Third-party** | Чужие компоненты — свои лицензии; см. карту / SBOM / NOTICE |
| **Слой / контур** | Рабочая среда организации поверх хост-ОС |
| **Self-hosted** | Запуск дара у себя |
| **Сопровождение (опция)** | Помощь с приёмкой/эксплуатацией; исходники остаются открытыми по MIT |
| **Артефакты приёмки** | Source, commit/tag, сборка, docs, SBOM — [P3f](03f-transfer-bom-handover.md) |
| **SI** | Интегратор / подряд внедрения |
| **Edition cloud / on-prem / client** | Где крутится контур — [P10](10-editions.md) |
| **Agentless** | Без системного агента на личной ОС как нормы доступа |
| **Сервисный доступ (seat / капсула)** | Доступ к hosted/доверенному каналу; **не** лицензия кода MIT |
| **E2EE (чат)** | Сквозное шифрование по согласию |
| **Edge / стена** | Default-deny снаружи + доступ по доверию |
| **MusicForge** | Актуальная «Студия песен» |
| **PoC** | Проверка реальных возможностей — [P3g](03g-si-migration-playbook.md) |
| **DD / вопросы** | [13-onepager-dd-rfi.md](13-onepager-dd-rfi.md) |
