# Как растить альбом семени жизни AMKA

## Где физически

Каталог: **`product/amka-seed-album/`**.

**Scope:** листы про **маркетинговую / standalone AMKA** (прогоны, драйверы, pulse). Документы **EWA** (companion, desktop orchestration, brand) кладите в **`product/ewa/`**, не сюда. Сравнительная таблица контуров — [AMKA-CONTOURS.md](AMKA-CONTOURS.md).

## Жанры документов (рекомендуется)

| Жанр | Имя / шаблон | Когда добавлять |
|------|----------------|-----------------|
| Вектор / манифест | `VISION-*.md`, `*-PRINCIPLES.md` | Смена смысла, новая ось продукта |
| RFC-черновик | `RFC-NNN-*.md` | Почти готовая идея драйвера или API ядра |
| Сессия мышления | `SESSION-YYYY-MM-DD-topic.md` | Сырой, но ценный разговор без немедленной канонизации |
| Решение (ADR-лайт) | `DECISION-YYYY-MM-DD-slug.md` | «Приняли X, отвергли Y», ссылка на мотивы |

Избегайте дублирования **операционной** документации кабинета: она остаётся в `product/marketing/amka/` и `AMKA-REFERENCE.md`. Не дублируйте сюда канон спутника EWA.

## Именование

- Латиница и дефисы в имени файла — проще для git и инструментов.
- Русский язык **внутри** файла приветствуется.

## Хронология

`documentation/worklog/` retired. Существенные дополнения альбома — строка в оглавлении [README.md](README.md) + краткий chat/`git log`; session-summary файлы только по явной просьбе оператора.

## Оглавление

Новый устойчивый документ добавьте строкой в таблицу в **[README.md](README.md)**.

## Принцип

**Альбом** может противоречить **текущему коду**: тогда альбом — про будущее standalone AMKA, а референс по маркетингу — про настоящее. Явно помечайте статус в начале файла: *«черновик»*, *«согласовано»*, *«отложено»* — по желанию.
