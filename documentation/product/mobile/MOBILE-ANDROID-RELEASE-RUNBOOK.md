# Mobile Android — release & CI runbook

## CI (`mobile-android-ci`)

- Workflow: `.github/workflows/mobile-android-ci.yml`.
- Uses Java 17, `android-actions/setup-android`, Gradle wrapper **8.13**.
- Quality gates (2026-06-02): `:core:network:testDebugUnitTest`, `:core:auth:testDebugUnitTest`, `:core:storage:testDebugUnitTest`, then `:app:lintDevDebug`, `:app:testDevDebugUnitTest`, `:app:assembleProdDebug`.
- Release APK for internal distribution: `./gradlew -Pmobile.android.ci=true :app:assembleProdRelease` signs the release build type with the **debug** keystore so the workflow does not require operator signing secrets. **Do not** ship those artifacts to public stores; see [pack-cloud/mobile/docs/SIGNING-PLAN.md](../../../pack-cloud/mobile/docs/SIGNING-PLAN.md).
- Version bump before publish: `bash pack-cloud/mobile/scripts/validate-version-bump.sh`
- Release notes draft: `bash pack-cloud/mobile/scripts/generate-release-notes.sh`
- **OTA user copy (обязательно RU):** `pack-cloud/mobile/docs/RELEASE-NOTES-user.ru.txt` — **только текущая версия** (один блок `Обновление EliteEW Mobile …`); читается при `serve-mobile-apk-tunnel.sh publish`. Проверка: `bash pack-cloud/mobile/scripts/validate-release-notes-user.sh`. Агрегация пропущенных версий — из `release_notes_history` + `installed_version_code` в API overview.
- **История пропущенных версий:** `pack-cloud/mobile/docs/RELEASE-NOTES-history.ru.json` — по одной записи на versionCode; upsert при publish; нормализация: `python3 pack-cloud/mobile/scripts/normalize-release-notes-history.py`.
- Release channels + rollback: [pack-cloud/mobile/docs/RELEASE-CHANNELS.md](../../../pack-cloud/mobile/docs/RELEASE-CHANNELS.md)
- Artifacts: CI uploads `app/build/outputs/apk/prod/debug/*.apk` plus lint/test reports. Prod release APKs are generated by the operator cycle below.
- Publish to API store: `bash docker/scripts/serve-mobile-apk-tunnel.sh publish` also writes `empery-mobile.apk.meta.json` (version for in-app update check) and packs `app-prod-release.7z` for Telegram (max compression, ≤50 MB).
- TG bot deploy step in the cycle calls `tg_bot_ip_verif/scripts/push-bot-remote.sh` when that tree is present. The operator bot tree is **soft-retired** under `trash/` — restore only on explicit request; otherwise use `--skip` / omit `--tg` and treat TG push as optional.


## Operator full cycle (one script)

```bash
# Interactive menu
bash docker/scripts/mobile-apk-release-cycle.sh
eec mobile-apk                    # same from container console
eemobile                          # after: source docker/scripts/eliteew-docker-aliases.sh

# Non-interactive (typical release)
eemobile --yes --all
# or: bash docker/scripts/mobile-apk-release-cycle.sh --yes --all
```

Steps in `--all` (order **2026-06-22**): Gradle `lintProdRelease` + `assembleProdRelease` (Crashlytics mapping upload skipped offline) → `serve-mobile-apk-tunnel.sh publish` (APK + 7z) → frontend build → **prod-core OTA rsync** (`deploy-prod-core-mobile.sh --ota`) → prod-core stack0 frontend (baked line A via `eeprodbaked` / preferred full release `bash docker/scripts/eliteew-deploy.sh release stack0 --all`, **or** `eeprodline up-dev-bind` when line B active) → optional TG push when `tg_bot_ip_verif/` is restored → smoke (local OTA + **prod-core OTA parity** + **API sidecar meta parity**).

**Hard gate (2026-06-22):** `mobile-apk-release-cycle.sh` calls `pack-cloud/mobile/scripts/validate-version-bump.sh` before `--build` and before `--publish` (when build was skipped). `versionCode` must be **strictly greater** than `local/binaries/empery-mobile.manifest.json`; otherwise the cycle exits before Gradle/publish.

**Gradle offline / LAN:** prod release adds `-x uploadCrashlyticsMappingFileProdRelease` and fails on non-zero Gradle exit (mapping upload must not block OTA when Firebase upload is unreachable).

**prod-core stack0 when dev-bind active:** if `.prod-line-state.json` has `active_line=dev-bind`, `--stack0` uses `eeprodline sync` + `up-dev-bind --yes` instead of `eeprodbaked` (which refuses while line B is active).

**Invariant (2026-06-19):** `--all` always pushes OTA to prod-core (`.111`). Phones read manifest via API from prod-core `:29180`, not command-center. Local-only publish: `--yes --all --skip-prod-core-ota` (smoke warns, does not fail parity).

## prod-core deploy (safe script)

**Canonical:** `docker/scripts/deploy-prod-core-mobile.sh` (alias `eeprodcore` after `source docker/scripts/eliteew-docker-aliases.sh`).

| Mode | Command |
|------|---------|
| OTA only | `eeprodcore --yes --ota` |
| API / SPA baked stack0 | Prefer **`bash docker/scripts/eliteew-deploy.sh release stack0 --all`** from command-center (wraps baked deploy). Line B hotfix: `eeprodline` per `platform/PROD-CORE-DEV-BIND-LINE.md`. |
| Publish + prod-core OTA (без полного цикла) | `eemobile --yes --publish --prod-core --smoke` |

**Удалено (2026-06-15):** `eeprodcore --api` и `--full` — скрипт завершается с ошибкой и указывает на `eeprodbaked`. Rebake на `.111` запрещён; preserved legacy copies в soft-retired under `trash/` (id 20260812-150051, was …/trash).

**Safety invariants (incident 2026-06-14):**

- **Do not** run `eectl prod-core recreate stack0-backend` on `.111` — it uses legacy compose without `stack0_*.prod-baked.override.yml` and breaks `:29000`/`:29001`.
- The deploy script always: validates `STACK0_*_BAKED_IMAGE` env, stops legacy non-`-baked` containers, recreates via prod-baked override compose, runs health smoke.

Manual OTA rsync (equivalent to `--ota`):

```bash
# После publish на build/command-center хосте:
rsync -avz local/binaries/ prod-core:<repo>/local/binaries/

ssh prod-core 'cd <repo> && \
  podman compose -f docker/stack/stack-mobile-release.yml up -d --force-recreate && \
  bash docker/scripts/mobile-release-stack.sh smoke 2>/dev/null || \
  curl -sf http://127.0.0.1:29180/v1/manifest.json'
```

Широкий deploy-tree (включает `local/binaries/`): `bash docker/scripts/sync-prod-core-deploy-tree.sh prod-core`.

Verify:

```bash
ssh prod-core 'cat local/binaries/empery-mobile.apk.meta.json'
ssh prod-core 'podman exec stack0-eliteew-api-prod-baked cat /app/mobile-release/empery-mobile.apk.meta.json'
```

UI/chrome policy for OTA acceptance: [MOBILE-ANDROID-SCALE-CHROME-POLICY.md](MOBILE-ANDROID-SCALE-CHROME-POLICY.md). Safe deploy incident lessons (2026-06-14) remain in this runbook § prod-core deploy.

Release invariant: every new prod OTA artifact must bump `defaultConfig.versionCode` in `pack-cloud/mobile/app/build.gradle.kts` before `--build --publish`; `versionName` should move with it. Reusing the same code only replaces the APK on edge and can be invisible to already installed clients.

Partial flags: `--build`, `--publish`, `--frontend`, `--stack0`, `--stack0-full`, `--tg`, `--smoke`, `--skip-lint`, `--prod-core` (OTA rsync на prod-core), `--skip-prod-core-ota` (отключить prod-core OTA внутри `--all`). **Удалено:** `--prod-core-api`, `--prod-core-full` — rebake API/SPA на `.111` запрещён; см. `eeprodbaked`.

## OTA Podman stack restart

After a prod OTA publish, the release script already runs `stack-mobile-release up` with force recreate. If an explicit OTA stack restart is requested, run:

```bash
bash docker/scripts/mobile-release-stack.sh down
bash docker/scripts/mobile-release-stack.sh up
bash docker/scripts/mobile-release-stack.sh smoke
bash docker/scripts/mobile-release-stack.sh status
```

`status` must show the same `version_code`, `version_name` and SHA-256 as `local/binaries/empery-mobile.manifest.json`.

## Smoke semantics

- `--smoke` is strict for local OTA integrity: `local/binaries/empery-mobile.manifest.json` must validate (`apk_available=true`, positive `version_code`, non-empty `version_name`, positive size, valid SHA-256) and `stack-mobile-release` must serve a valid `/v1/manifest.json`.
- **Continuous OTA (W0, 2026-07-16):** every `--smoke` (включая без `--all`) **fails** if prod-core `:29180/health` unreachable (`verify_prod_core_ota_alive`). Fix: `ssh prod-core 'bash docker/scripts/prod-core-mobile-ota-start.sh'` or `deploy-prod-core-mobile.sh --yes --ota`. Boot autostart: phase `mobile-ota` in `podman-autostart-prod-core.sh`.
- When `--all` or `--prod-core` ran in the same invocation, smoke **requires** prod-core (`ssh prod-core`, `:29180/v1/manifest.json`) to match local manifest (`version_code`, `sha256`). Mismatch fails the cycle with a fix hint (`deploy-prod-core-mobile.sh --yes --ota`).
- Same strict mode also compares `podman exec stack0-eliteew-api-prod-baked cat /app/mobile-release/empery-mobile.apk.meta.json` to local manifest (`version_code`, `sha256`). `GET /api/v1/mobile-app/overview` needs auth; the sidecar check is the operator smoke for in-app update metadata.
- `--publish` without `--prod-core`: smoke warns if prod-core is behind local; use `--prod-core` or full `--all` before expecting phones to update.
- `mobile-release-stack.sh smoke` also checks APK **HEAD** / **Range: bytes=0-0** on `/v1/empery-mobile.apk` and warns if stack0 overview is reachable.
- Public edge `/mobile-app/` HEAD checks are warning-only because they depend on external routing/tunnel state.
- `serve-mobile-apk-tunnel.sh publish` validates manifest size/hash against `local/binaries/empery-mobile.apk` immediately after writing it; `status` runs the same validation.
- Backend `GET /api/v1/mobile-app/overview` must bypass the generic Redis response cache. If the app shows an old server version after publish, check `api/middleware/response_cache.py` exclusions and redeploy prod-core stack0 via `bash docker/scripts/eliteew-deploy.sh release stack0 --all` (container `stack0-eliteew-api-prod-baked`); the endpoint should read live `stack-mobile-release` manifest or `/app/mobile-release/empery-mobile.apk.meta.json`.

### Secure Connection post-bind checklist (W0 / C2)

После успешного `POST /api/v1/mobile-devices/bind` (или rotate-wg / revoke) в production:

1. Дождаться Celery `mobile_wg_edge_sync_ok` **или** `tunnel.edge_sync_status=synced` (не путать с `tunnel.status=ready`).

## Firebase / FCM (push) — обязательно для prod OTA с push

Push в prod **не работает**, пока не выполнены оба контура:

| Контур | Файл / env | Где лежит |
|--------|------------|-----------|
| **Android APK** | google-services.json *[local under pack-cloud/mobile/app/; not in git]* | command-center `.136`, **не в git** (`.gitignore`) |
| **stack0 API** | `MOBILE_FCM_ENABLED=true`, `MOBILE_FCM_PROJECT_ID`, `MOBILE_FCM_SERVICE_ACCOUNT_JSON` | `docker/env_file/.env.stack0.backend` → SOPS bundle → prod-core runtime tmpfs |

### Перед `eemobile --yes --build --publish`

1. Убедиться, что google-services.json *[local under pack-cloud/mobile/app/; not in git]* существует на build-хосте (package `world.empery.mobile`, проект Firebase совпадает с `MOBILE_FCM_PROJECT_ID`).
2. `bash pack-cloud/mobile/scripts/validate-version-bump.sh` — `versionCode` должен вырасти.
3. После publish проверить на prod-core: FCM token в БД (`user_mobile_push_tokens`) и `fcm_configured=True` в API.

Service account JSON для бэкенда: `docker/data/mobile-fcm/firebase-service-account.json` (тоже **не в git**). Inline в env — через **Config Plane** / `eliteew-prod-core-env-push.sh` (historical script name; EliteEW env push to prod-core tmpfs).

Без `google-services.json` Gradle-сборка проходит, но Firebase не инициализируется — токены на сервер не попадают, push молчит.

### Firebase credentials — Git и ротация

- В tracked `docker/env_file/.env.stack0.backend.example` FCM всегда безопасно выключен: `MOBILE_FCM_ENABLED=false`, а `MOBILE_FCM_SERVICE_ACCOUNT_JSON` пуст. Настоящий JSON сервисного аккаунта в `*.example` запрещён.
- google-services.json *[local under pack-cloud/mobile/app/; not in git]* и `docker/data/mobile-fcm/firebase-service-account.json` остаются локальными gitignored-файлами. Наличие записи в `.gitignore` не удаляет файл, который уже был tracked.
- Подозрение на публикацию private key означает немедленный отзыв ключа в Google Cloud. Private-видимость репозитория не считается защитой и не позволяет повторно использовать такой ключ.
- При намеренно выключенном production новый ключ не создаётся. Для последующего включения: создать новый JSON → положить только в локальный Config Plane → обновить SOPS/runtime env → проверить `fcm_configured=True` и реальный push → лишь затем оставить `MOBILE_FCM_ENABLED=true`.
- Перед публичным root snapshot: Gitleaks по чистому tracked snapshot должен завершиться без находок; полный private history проверяется отдельно и никогда не становится публичным.

### Smoke после OTA с push

- Android 13+: при первом входе — диалог «Разрешить уведомления?»; при отказе — баннер с «Разрешить сейчас».
- Заблокировать экран 10–15 мин, отправить сообщение/звонок с другого аккаунта — push должен прийти.
- Профиль → Уведомления: нет красного баннера «Уведомления заблокированы Android».

## Firebase / Crashlytics (optional plugins)

- `google-services.json` is optional in repo. When present at google-services.json *[local under pack-cloud/mobile/app/; not in git]*, the app module applies `google-services` and Crashlytics plugins automatically.
- Without the file, Firebase init is best-effort at runtime (`MobileApp`).

## Operator signing (production)

- Define a release keystore and Gradle properties (example names only; do not commit secrets):
  - `MYAPP_RELEASE_STORE_FILE`, store password, key alias, key password.
- Wire `signingConfigs.release` in `pack-cloud/mobile/app/build.gradle.kts` and set `buildTypes.release.signingConfig` to that config when **not** using `mobile.android.ci=true`.
