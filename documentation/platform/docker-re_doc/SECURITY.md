# Docker: безопасность и переименование команд

Внутренний документ. Соответствие сетей и сервисов — см. [SEGMENTATION.md](SEGMENTATION.md). **Модель угроз контейнеров с учётом периметра edge+NAT+SG** — [CONTAINER-SECURITY-THREAT-MODEL.md](CONTAINER-SECURITY-THREAT-MODEL.md).

## Зоны угроз (кратко)

| Слой | Контроль compose | Контроль периметра |
|------|------------------|-------------------|
| Internet → сервис | bind `127.0.0.1`, `ew_net_*` | edge SG, Meet WG primary, SSH reserve |
| LAN → stack1 / llama | `STACK1_CLIENT_BIND`, firewalld/nftables | Нет dst-nat WAN→prod-core |
| Контейнер → data-tier | сегментация сетей, пароли env | auth vector DB (gap — см. threat model) |

Переименование опасных команд Redis ниже — **defense-in-depth** при компрометации клиента **внутри** доверенной зоны, не замена периметра.

## Стандарт переименования опасных команд

**Цель:** затруднить использование служебных/деструктивных команд извне (изменение конфига, завершение работы, выполнение произвольного кода, репликация и т.п.). Сокращение поверхности атаки при компрометации клиента или утечке доступа к порту.

**Формат:**

- Переименовать команду в непредсказуемое имя вида `<CMD>_<короткий_хеш_или_случайный_суффикс>` (например `CONFIG_b8f3d2a9e4c1`). Суффикс не должен быть очевидным (избегать 0001, 1234 и т.д.).
- Либо **отключить** команду, если сервис это позволяет (например, Redis можно переименовать в `""`, чтобы команда стала недоступна).

**Какие команды считать опасными:**

- Управление конфигурацией (CONFIG, настройка путей, параметров).
- Завершение работы (SHUTDOWN и аналоги).
- Загрузка/выполнение кода (MODULE, DEBUG, eval-подобные).
- Репликация и клонирование (REPLICAOF, SLAVEOF и т.п.).
- По документации конкретного сервиса — любые команды/API с пометкой `@dangerous` или «только для отладки/администрирования».

**Где применять:**

- Только в сервисах, которые поддерживают переименование или отключение команд на уровне конфигурации.
- Если сервис не поддерживает переименование — опираться на аутентификацию, привязку портов к 127.0.0.1 и сегментацию сетей; зафиксировать это в документации (см. разделы RabbitMQ, Elasticsearch ниже).

## Redis (stack/stack1.yml)

Поддерживает `--rename-command`. Переименованы:

| Команда   | Новое имя           |
|-----------|----------------------|
| CONFIG    | CONFIG_b8f3d2a9e4c1  |
| SHUTDOWN  | SHUTDOWN_a7e2c9b4f1d3 |
| DEBUG     | DEBUG_c4e1a9f2d7b3   |
| MODULE    | MODULE_e8b2d5a1c9f4 |
| REPLICAOF | REPLICAOF_f3a6c8e2b1d9 |

Дополнительно: `requirepass`, порты привязаны к **127.0.0.1 в prod** (см. `STACK1_CLIENT_BIND`), сегментация сети. LAN bind для workers — только с firewalld; см. [LAN-WORKERS-141.md](LAN-WORKERS-141.md).

Логи Redis идут в **stdout** (`--logfile ""`), драйвер Docker `json-file`. Отдельный том `../logs/stack1/redis` для файла лога не используется: при `user: STACK1_UID_DB` запись в смонтированный каталог часто даёт *Permission denied*.

## RabbitMQ (stack/stack1.yml)

Переименование или отключение отдельных команд/API в конфигурации **не поддерживается**. Опора на:

- сильную аутентификацию (`RABBITMQ_DEFAULT_USER` / пароль из env);
- привязку портов к 127.0.0.1 (5672, 15672);
- конфигурацию в `rabbitmq/conf.d/` (в т.ч. отключение устаревших метрик);
- сегментацию сети (доступ только нужным сервисам).

## Elasticsearch (stack/stack1.yml)

Переименование или отключение отдельных API в конфигурации **не поддерживается**. Опора на:

- привязку порта к 127.0.0.1;
- сегментацию сети;
- при необходимости — включение `xpack.security.enabled` и ограничение доступа по ролям (настраивается отдельно).

Снимки в S3: если понадобятся `AWS_CONFIG_FILE` / `AWS_SHARED_CREDENTIALS_FILE`, смонтировать **файлы** в `docker/data/stack1/elasticsearch_config/`, а не пустые каталоги с тем же именем (иначе WARN от плагина AWS при старте).

## Остальные сервисы

Для сервисов с CLI/API, позволяющим менять конфиг или выполнять код: проверить документацию на поддержку переименования/отключения команд и применить тот же подход, где возможно.
