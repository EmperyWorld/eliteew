# Верификация кода агентом Cursor: до задачи, в процессе, после (требования)

**Статус:** обязательный процесс для агентских правок в монорепозитории **powered_by_emperyworld** / приложение **EliteEW**, если среда позволяет выполнить шаги.  
**Правило Cursor (сжатое):** `.cursor/rules/agent-code-verification.mdc`.  
**Связь с уставом:** `.cursor/rules/eliteew-user-workflow-preferences.mdc` (критерий завершения дополняется семантическим слоем, а не заменяется).  
**Closeout:** layers A–E remain the semantic bar; general hard-acceptance theater is **retired**. For Tauri trust-boundary paths use [AGENT-TAURI-SECURITY-WORKFLOW.md](AGENT-TAURI-SECURITY-WORKFLOW.md). Commit only on operator request ([AGENT-VERIFIED-PROPOSAL-PROTOCOL.md](AGENT-VERIFIED-PROPOSAL-PROTOCOL.md)).

## 1. Зачем этот документ (выводы из реального инцидента)

В одной цепочке (**спутник → действия → нормализация → HTTP PATCH → персист**) одновременно проявились:

1. **Логическая дыра, невидимая линтеру:** обязательная проверка поля, неприменимого к типу действия (`app_component` до ветки `patch_desktop_config`), из‑за чего валидное действие **молча отбрасывалось** на границе парсера.
2. **Альтернативный путь выполнения:** ранний ответ оркестратора **не вызывал** ту же функцию финализации действий, что и «длинный» LLM‑путь, поэтому детерминированное дополнение сценария **не срабатывало** на части ходов.
3. **Ложное чувство готовности:** «зелёный» Ruff и узкие тесты** одного** слоя (например, только HTTP‑транспорт) **не доказывают**, что **данные доходят** до этого слоя с реальной формой JSON.

**Инвариант процесса:** линтер и форматтер — **необходимы, но недостаточны**. Обязателен хотя бы один **семантический** контроль: трассировка данных и/или тест на **границе контракта**.

## 2. До начала работы (обязательные шаги)

Выполнить в разумном объёме; если шаг невозможен — зафиксировать **блокер** в ответе оператору.

| Шаг | Что сделать | Зачем |
|-----|-------------|--------|
| **2.1 Домен** | Открыть существующий документ по теме в `documentation/` (см. `documentation-maintenance.mdc`, `documentation/INDEX.md`). | Не противоречить зафиксированному контракту и терминам. |
| **2.2 Воспроизведение** | Для бага: логи / шаги / ожидаемое vs фактическое **до** правок кода (`project-and-deploy.mdc`). | Исключить исправление «не той» ветки. |
| **2.3 Точки входа и выхода** | Явно назвать: HTTP‑роут, очередь, CLI, фронтовый вызов → какой модуль → какой побочный эффект (БД, файл, другой HTTP). | Карта для трассировки в п. 4.2. |
| **2.4 Ветвления** | Поиск по коду (`grep`/«codebase») по **уникальным** строкам: `return` до основного пути, `if orchestrated`, `early`, `short-circuit`, альтернативные хендлеры. | Новая логика часто забывается в **одной** из веток. |
| **2.5 Контракт данных** | Для JSON/действий/intent: где **нормализация**, **валидация**, **санитайзер**; одна строка: «что считается отсутствующим полем и чем это чревато». | Предотвращение молчаливого отбрасывания payload. |

## 3. Во время работы

| Практика | Требование |
|----------|------------|
| **Минимальный diff** | По умолчанию — как в `eliteew-user-workflow-preferences.mdc`. |
| **Пауза каждые ~5–8 файлов** | `ruff check` по затронутым путям (Python) / эквивалент для фронта — чтобы не копить синтаксические ошибки. |
| **Симметрия веток** | Если поведение должно совпадать в «длинной» и «короткой» ветке — явно сверить **обе** (или вынести общую функцию и вызвать из обеих). |
| **Порядок предикатов** | При разборе union‑типов (разные `type` / `kind`) в одной функции — в коде и в голове: **сначала** ветки без общих обязательных полей, **потом** общие ограничения; либо ветка «раньше return» с полным набором полей. |

## 4. После выполнения задачи (слои проверки)

Порядок важен: **сначала инструменты стиля**, затем **семантика**, затем **документация/ответ**.

### 4.1 Слой A — инструменты (обязательно, если среда позволяет)

- **Python:** из каталога `shared/api`: `uv run ruff format <пути>` и `uv run ruff check <пути>` по **всем** изменённым `.py` (см. `coding-standards.mdc`).
- **Frontend:** по `code-quality.mdc` — `biome format` и `biome check` по **всем** изменённым `src/**/*.{ts,tsx,css}`.
- **Заголовки файлов:** `eliteew-file-authorship.mdc` на всех затронутых файлах из области действия правила.

**Явно указать в ответе:** слой A выполнен или **блокер** (какая команда недоступна).

### 4.2 Слой B — трассировка данных (обязательно для задач из триггеров §5)

Кратко, в голове или в ответе оператору (3–8 пунктов):

1. Пользователь / клиент / воркер формирует **сырой** объект.
2. Где он **нормализуется** / фильтруется / отбрасывается без исключения?
3. Все **ранние return** на пути: получает ли каждый тот же инвариант?
4. Где **побочный эффект** (БД, HTTP, событие) и совпадает ли с документированным контрактом?

Если обнаружено «данные могут не дойти» — **исправить код или тест** до завершения задачи.

### 4.3 Слой C — поведенческие тесты (обязательно по триггерам §5)

- Тест размещается рядом с существующими тестами домена (`shared/api/tests/`, Vitest для фронта — по `frontend-tests.mdc` / `code-quality.mdc`).
- Минимум: **один** тест «вход (строка / dict) → ожидаемая структура или вызов» на **границе**, где была или могла бы быть молчаливая потеря данных.
- Узкие моки транспорта **не заменяют** тест нормализатора/роутера, если баг был в форме объекта **до** транспорта.

### 4.4 Слой D — операторская smoke (при изменении UX/API)

Короткая инструкция: куда зайти, 2–5 действий, что увидеть — как уже требует `eliteew-user-workflow-preferences.mdc`.

### 4.5 Документация

По `documentation-maintenance.mdc`: существенный контракт или процесс — переписать живой канон в `documentation/product/`, `documentation/platform/`, `documentation/api/`, `documentation/database/`, `documentation/reference/`. **`documentation/worklog/` retired** (stub README only) — не вести monthly journals; хронология: chat summary + `git log`. Session-summary CLI — только по явной просьбе оператора (`session-summary-files.mdc`).

### 4.6 Слой E — структурные изменения роутеров (обязателен при split/move)

Когда задача **делит, переносит или объединяет** модули FastAPI (`api/routers/*.py`), god-file remediation или mount/re-export — **нельзя** закрыть только слоем A.

Канон: **`documentation/platform/ATOMIC-ROUTER-DECOMPOSITION-CANON.md`**. Milestone: desktop router decomposition (EV-02, 2026-07-04).

| Шаг | Действие |
|-----|----------|
| **E1 — Import / re-export chain** | `rg` по символам до/после; родитель re-export'ит; `from api.routers.desktop import …` и legacy import sites работают. |
| **E2 — Dependency direction** | Нет новых циклов между sibling-модулями (desktop: `bootstrap`/`items`/`recents` ↛ `desktop_workspace`). |
| **E3 — URL stability** | `include_router` без лишнего `prefix`; пути `@router.get/post/…` на перенесённых routes не меняются. |
| **E4 — Regression** | Узкий pytest + import-chain test (пример: `tests/test_desktop_items_import_chain.py`). |

Phase 0 (Dependency Impact Analysis) и target LOC — см. `task-intake-and-risk-gate.mdc` §Structural tasks.

## 5. Триггеры: когда слои B и C обязательны без исключений

Если выполняется **хотя бы одно** из условий ниже — **нельзя** закрыть задачу только слоем A.

| Триггер | Обязательно |
|---------|--------------|
| Новый или изменённый **тип** структурированного действия / сообщения / intent (например, поле `type`, `intent_kind`). | **B + C**: трассировка + тест на нормализацию или парсер. |
| Новая или изменённая **ветка** с ранним `return` полного ответа (оркестратор, prefetch, fallback). | **B**: явное сравнение с основной веткой; при разном поведении — **C** на обеих. |
| Новый **выходной HTTP** или вызов API «сам на себя» / driver stub. | **C**: минимум тест на форму тела/заголовков **или** e2e с мок‑транспортом плюс тест upstream‑нормализатора (если применимо). |
| Изменение **одной функции**, через которую проходят **несколько** типов payload (общий `_normalize_*`, `sanitize_*`). | **B**: для каждого типа — путь не отфильтрован раньше времени; **C**: по одному тесту на тип при риске. |
| **Split / move / merge** FastAPI router modules (`api/routers/`), re-export or mount refactor. | **E** (§4.6): import chain, dependency direction, URL stability, narrow pytest. |

---

## 5b. Триггеры слоя E (структурные роутеры)

Слой **E** обязателен без исключений, если выполняется **хотя бы одно**:

| Триггер | Обязательно |
|---------|-------------|
| Новый файл `api/routers/<domain>.py` с переносом handlers из god-file. | **E1–E4** |
| Изменение `include_router` / prefix / mount order в parent router. | **E3** + grep paths |
| Перенос schemas/helpers между router modules. | **E1** re-export chain |
| Любой новый import между `desktop_shell`, `desktop_items`, `desktop_workspace`, `desktop_bootstrap`. | **E2** cycle check |

Docs-only governance updates (rules/canons) — Layer E **не** применяется.

## 6. Антипаттерны (запрещено считать задачу выполненной)

- «Зелёный Ruff/Biome — значит работает»: **нет**, если не пройдены §4.2–4.3 по триггерам §5.
- Один узкий интеграционный тест **ниже** места потери данных без теста **на** месте потери.
- Добавление логики только в «основную» ветку без grep по **всем** вызовам финализации / merge действий.
- Закрытие задачи без списка изменённых файлов и без явного статуса слоёв A–C (или блокера).

## 8. Согласование с другими правилами (противоречия и непридуманные «глупости»)

Этот раздел фиксирует **частые трения**, а не дублирует весь каталог `.cursor/rules/`.

| Зона | Риск | Как не ломать процесс |
|------|------|------------------------|
| **`ewa-platform-default.mdc`** vs пути `features/amka/` | Имя каталога **`amka`** на фронте связано с историей, но **спутник на столе** относится к **EWA/desktop**, не к маркетинговой AMKA — агент ошибочно режет scope. | В scope перечислены **companion routers/services** и явные пути **`EwaCompanionChatPanel.tsx`**, **`ewaCompanionChatApi.ts`**; не отрезать задачу только из‑за `amka/` в пути. |
| **`desktop-shell-and-windows.mdc`** (широкие globs) | Правило может подсветиться на постороннем фронте. | В самом правиле указано: смысл — **оболочка стола** / **`DesktopWindowLayer`**; вне `pages/Desktop` — только при затронутых примитивах. |
| **`code-quality.mdc`** vs **`eliteew-user-workflow-preferences.mdc`** | В одном месте — «минимум **build:react-compiler** после правок фронта», в другом чеклисте раньше упор только на Biome. | В уставе агента пункт про фронт явно ссылается на **`code-quality.mdc`** и build; при блокере среды — **блокер** в ответе, не «тихий пропуск». |
| **`documentation-maintenance.mdc`** vs User Rules «не трогай .md» | Агент тормозит существенную фиксацию. | В **`documentation-maintenance.mdc`** зафиксирован приоритет workspace при существенных изменениях; явный запрет оператора в **сообщении задачи** имеет приоритет. |
| **`frontend-tests.mdc`** vs **`agent-code-verification.mdc`** | «Обязательного CI может не быть» vs «тест на границе обязателен по триггерам». | Нет противоречия: **триггерный** тест локально/в PR — обязателен процессом верификации; отсутствие CI — не оправдание пропустить **C** без блокера. |
| **`ugs-workflow-builder.mdc`** | Роут **`workflowBuilderRoute`** без полного пути. | Канон: **workflowBuilderRoute.ts *[retired with WorkflowBuilder]***. |

## 9. Уместность правила (когда B/C не нужны)

Правило **не** требует трассировку и поведенческий тест на **каждую** правку. Слой **A** (Ruff/Biome, заголовки, сборка) достаточен, если **ни один** триггер из §5 не сработал.

| Тип задачи | B/C | E |
|------------|-----|---|
| Документация, комментарии без смены контракта | Не обязательны | Не обязателен |
| Зависимости, override transitive, косметика UI без нового intent/action | Не обязательны | Не обязателен |
| Новый `type` / intent, общий `_normalize_*`, ранний полный ответ оркестратора | **Обязательны** | Не обязателен |
| Split/move/merge `api/routers/*.py`, mount/re-export refactor | По контракту | **Обязателен** (§4.6) |

В ответе агенту достаточно строки: «семантические триггеры §5 не применялись: …» или «слой E выполнен / N/A: …» с краткой причиной.
