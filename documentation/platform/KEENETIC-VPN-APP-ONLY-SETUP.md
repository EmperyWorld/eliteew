## Текущая физика (кратко)

| Кабель | Куда | Назначение |
|--------|------|------------|
| **Keenetic WAN** | **MikroTik ether10** (`br-guest`, **192.168.50.x**) | Wi‑Fi клиенты Keenetic → интернет |
| **ether5** | Резерв в `bridge` (кабель Keenetic **не** используется) | Исторический «второй LAN» снят — см. §Historical ниже |

**Wi‑Fi сегменты** (`192.168.60.x` и т.п.) задаются **на Keenetic**, не через отдельный линк ether5.

## WireGuard «только app» (living)

1. На Keenetic: **WireGuard VPN-сервер**, порт например **51822** (не пересекай Meet WG **51821** / mobile WG).
2. Пул клиентов, например **10.200.0.0/24**.
3. У peer в **Allowed IPs** — **только** **192.168.1.136/32** (не `0.0.0.0/0`).
4. Изоляция клиентов VPN; без дефолтного маршрута в интернет.
5. Снаружи (если нужно): MikroTik WAN **dst-nat UDP → 192.168.50.199:51822** — см. runbook §7.

### Проверка

- Wi‑Fi на Keenetic: интернет есть (через **ether10**).
- VPN-клиент: открывается только [https://192.168.1.136/](https://192.168.1.136/) (или имя **app**), не произвольный сайт и не **192.168.1.141**.

## Компоненты KeeneticOS: что ставить / что нет

Ориентир: **Wi‑Fi + интернет через WAN (ether10)** + опциональный **WireGuard-сервер** «только app» на **136**.

### Оставить / обязательные для твоей схемы

| Компонент | Зачем |
|-----------|--------|
| **Мастер первоначальной настройки** | Уже есть — ок |
| **Интерфейс Wi‑Fi** | Нужен |
| **Сервер DHCP** | Нужен для клиентов на LAN/Wi‑Fi |
| **WireGuard VPN** + **WireGuard VPN-сервер** | Опциональная home-точка «только app» (не Meet WG / не public edge) |
| **Сетевой ускоритель** | Обычно оставляют |
| **Прокси IGMP/PPPoE** | Оставь, если провайдер/WAN так требует; иначе можно не трогать |
| **Клиент PPPoE** | Только если **WAN** Keenetic к провайдеру по PPPoE. У тебя WAN в **192.168.50.x** от MikroTik — чаще **не** PPPoE; если интернет на Keenetic уже работает без PPPoE — компонент можно **не** ставить / снять |
| **Клиент 802.1X** | Только если провайдер требует 802.1X на WAN — иначе не обязателен |

### Поставить по желанию (удобство)

| Компонент | Комментарий |
|-----------|-------------|
| **Сервер SSH** | **Рекомендую** — доступ к CLI для настройки и отладки |
| **Контроллер Wi‑Fi-системы** | Если несколько точек Keenetic — да; одна точка — можно без |

### Лучше не ставить / снять (безопасность и простота)

| Компонент | Почему |
|-----------|--------|
| **Служба UPnP** | Авто-дыры в NAT/фаерволе; при жёсткой политике **не** ставить |
| **PPTP VPN-сервер / клиент PPTP** | Устарело и небезопасно |
| **Клиент L2TP / PPTP** | Не нужен, если провайдер не требует |
| **EoIP / GRE / IP-IP туннели** | Нужны только если связка с **другим** MikroTik по этим протоколам; для **WireGuard + обычный WAN** — **не** ставить, лишнее |
| **OpenVPN / SSTP / L2TP IPsec серверы** | **Не primary.** Не ставить: публичный путь = Meet WG; home VPN = WireGuard. OpenVPN home stacks retired → `trash/` |
| **WPA Enterprise** | Только с RADIUS; дома обычно **не** нужно |

### Облачный DNS / фильтрация (NextDNS, SkyDNS)

| Компонент | Комментарий |
|-----------|-------------|
| **NextDNS / SkyDNS** | Для «только app» и предсказуемого DNS **можно не ставить** или **не** вешать на профиль VPN-клиентов — иначе трафик уходит в облако DNS. Для обычного Wi‑Fi дома — по желанию (родительский контроль и т.д.) |

Если помечены **«Обязательный»** системой — оставь как есть (часто **DNS-over-TLS/HTTPS**, шейпер).

### Диагностика и прочее

| Компонент | Комментарий |
|-----------|-------------|
| **iPerf3** | По желанию для замеров |
| **Агент облачных служб** | По желанию (удалённый доступ через облако Keenetic) |
| **DDNS-клиент** | Имеет смысл, если у Keenetic **белый** IP на WAN; за MikroTik с CGNAT — часто бесполезно |
| **ALG (FTP, SIP, …)** | Ставить **только** если реально используешь эти протоколы через NAT |
| **OpenConnect / ZeroTier / …** | Не нужны, пока не появится задача |

**Итог минимум для твоей задумки:** **Wi‑Fi + DHCP + WireGuard (и сервер) + то, без чего Keenetic не даёт обновиться**. **UPnP — нет.** **EoIP/GRE/IP-IP — нет**, если не строишь туннель к другому MikroTik. **SSH — да**, если хочешь копаться в CLI.
